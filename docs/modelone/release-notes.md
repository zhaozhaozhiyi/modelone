# modelOne 0.1.0-dev 版本说明

日期：2026-09-22。发布标签建议 `modelone-v<主版本>.<次版本>.<修订号>`；不兼容接口或数据变化升级主版本，功能迭代升级次版本，修复升级修订号。正式标签仅在验收通过后创建。

本次改动：统一品牌配置及运行时公开配置（含辅助色、登录背景/面板色和字体）；三个前端品牌入口和独立登录页；服务端导航、错误页和展示文案；初始化及示例数据；资源清单和企业仓库解析；保留兼容标识的数据迁移；部署渲染和发布扫描；企业镜像计划统一接入 Compose/Kubernetes/Argo 产物；支持整棵 Kubernetes 清单树的镜像重写（含 Kustomize `images`）；正式 Compose 使用镜像内代码、命名数据卷和显式 kubeconfig；集群启动入口强制使用已扫描的发布清单，并通过 `MODELONE_SERVICE_EXTERNAL_IP` 注入节点地址；Ingress 升级到 `networking.k8s.io/v1` 并支持企业域名/TLS；移除已废弃的 HPA/RBAC API；交付文档、CycloneDX 前端 SBOM 与许可证收集工具。

部署脚本补充节点地址必填校验，并统一规范化和引用企业资源下载地址，避免空参数或尾随斜杠导致启动过程延迟失败。

发布渲染现在强制传入由完整 Kubernetes 清单生成的镜像计划，避免遗漏第三方镜像重写而生成仍依赖旧仓库的交付产物。Ingress、Gateway 和 VirtualService 会使用统一企业域名，配置 TLS Secret 后生成 HTTPS 入口；Ingress 使用 Kubernetes `networking.k8s.io/v1` API。

镜像计划还必须与当前 `MODELONE_IMAGE_REGISTRY` 一致，防止切换企业仓库后误用旧计划。

修复发布清单树遗漏 Kustomize generator 文件的问题；交付目录携带明确引用的配置文件，并拒绝缺失文件、越界引用和与源码重叠的输出目录。镜像参数按完整引用一次替换，重复渲染不会叠加企业仓库前缀。CI 从发布目录实际构建主平台与训练控制器，再核对镜像计划并扫描产物。

发布渲染同时拒绝计划中指向其他仓库的单条目标镜像，避免手工修改计划绕过企业命名空间约束。清单重写支持通过 `publicDomain`/`tlsSecretName` 或对应环境变量生成企业域名和 HTTPS Gateway，空配置仍保留开发用通配 HTTP。

遗留主题示例中的占位名称也改为读取统一 modelOne 品牌配置，避免误用示例主题时显示非产品名称。

三个前端入口都声明 modelOne 触控图标，运行时品牌脚本会同步更新 favicon 与触控图标。

修复此前批量替换引入的问题：文生图 `$text` 和多轮对话占位符恢复，知识库文件路径对齐，容器挂载目录恢复兼容路径，迁移不再重命名作业或吞掉 SQL 错误，Kubernetes 品牌标签不再修改不可变选择器。

本地验证：三个生产前端构建成功；三十一项品牌/发布和七项认证回归通过；Notebook 九项中八项通过、一项条件跳过，节点五项和资源十项通过，镜像包十项在本地缓存镜像上通过，CI 还会使用前端交付镜像执行真实保存/导入；产品源码、任务模板、统一品牌配置、遗留主题模板、legacy `appbuilder` 静态资源及编译包品牌扫描通过，旧静态 jQuery 的 source-map 引用已移除；生产构建无 source map；PWA 清单由统一品牌配置生成并随三个前端构建；Compose 配置和 Kustomize 清单解析通过。现有构建仍有 lint/依赖与包体积警告。CI 构建保留这些告警，品牌和 source map 扫描独立作为失败门禁；尚未运行远程 CI。

补充修复：旧 Logo 回退、任务模板说明中的旧品牌与无效链接、存量镜像文档和预览资源字段；教程目标文件名与页面对齐；独立编排器和问答示例图读取企业存储配置；资源清单修正语音 CSV 地址并展开四张问答示例图；任务模板扫描纳入发布门禁，并移除 YOLOv8 Dockerfile 中不存在的旧安装钩子。

容器验证与修复：恢复镜像内 PWA 清单，Nginx 拒绝公开 source map，构建时清除旧静态文件，镜像附带原 LICENSE；后端镜像补齐运行配置；移除数据库 URI、登录密码及启动命令的敏感日志。隔离 MySQL 8.0.46 迁移和备份恢复、三个前端静态入口 HTTP 检查、本地空库初始化与后端基础页面请求均已通过。验证使用已缓存的基础镜像，尚未在企业仓库镜像上复测。

认证修复：移除用户名免密码登录、Host 信任绕过和未知用户自动注册；密码登录强制 CSRF，API 凭据校验签名、有效期和用途；停用账号不能继续使用会话或令牌。会话/JWT 密钥独立注入，初始管理员使用随机密码，重复初始化保留既有密码。新增七项认证回归，隔离容器的正常/异常登录、令牌和会话检查通过。

部署和升级影响：必须先准备 Compose 私密环境文件，或 Kubernetes 的 `modelone-auth`、`modelone-infrastructure` 和新安装所需的 `modelone-mysql` Secret；重新签发 SDK 凭据并重新生成已有任务。新任务使用限于业务 API 的令牌，四类启动器移除用户名回退和调试跟踪，需要重建任务镜像。历史明文密码账号需管理员重设。API 路径和存储/CRD 标识保持兼容，旧免验证认证方式不再兼容。详见 `upgrade.md`。

生产仍需落实企业认证选择、数据库/Redis 的私密配置、生产启动和 HTTPS 入口、任务凭据迁移及完整安全检查，详见 `security-review.md`。

待验收：自有 Git 仓库切换、正式品牌资产、943 个资源和 147 个镜像的筛选与迁移、媒体内容中的旧品牌检查、最终容器 SBOM、生产凭据和域名/TLS、认证、真实全新安装和升级、业务功能回归、离线与备份恢复验证。清单数量含历史示例，不等于最终运行依赖数量。

禁止将此开发基线描述为“全部验收通过”。

代码管理：开发分支为 `codex/modelone-brand-baseline`，原仓库已改为只读 `upstream`（禁用 push）。自有仓库地址未提供，尚未设置新的 `origin` 或创建正式发布标签。
