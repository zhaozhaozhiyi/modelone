## 生产发布阻断项

| 问题 | 当前源码证据 | 生产验收要求 |
| --- | --- | --- |
| 登录参数可以直接建立账号会话 | 两份部署 `project.py` 中，`/login/` 的 `username` 参数以及 `/login/api/` 的 `token` 参数用于按用户名查找并直接登录 | 按选定认证方案改为验证密码或受信任身份提供方凭证；验证伪造参数无法登录 |
| Host 判断参与内部身份绕过 | `myapp/security.py` 的 `load_user_from_header` 将含内部服务名的 Host 视为可免验证用户名认证 | 移除依赖可伪造 Host 的信任判断；为内部作业配置经过验证的服务凭据并回归调用方 |
| 固定开发签名密钥和管理员密码 | 部署配置的 `SECRET_KEY`、安全模块默认 JWT 密钥、初始化脚本的管理员默认凭据 | 通过企业密钥管理或 Secret 注入独立随机值；制定旧令牌失效和管理员初始化策略 |
| 自动注册与配置不一致 | 部署 `project.py` 在未知用户名提交登录时自动创建用户，而配置为 `AUTH_USER_REGISTRATION=False` | 按企业账号策略实现并验证禁止注册、受控邀请或身份提供方同步 |
| 认证类型尚未接入企业方案 | 安全管理器当前只接受 `AUTH_DB` | 用户确定本地账号、LDAP、OIDC 或企业认证后，实现相应回调、会话和角色映射并验证 |

以上是已定位的现有行为，不能仅通过改品牌、设置域名或执行 `--release` 渲染来解决。当前基线仅可用于隔离开发验证，不应直接作为安全验收通过的生产发行版。

本记录不公开真实凭据。复测应使用隔离测试账号；生产修复还需覆盖既有任务、SDK 和自动化调用的兼容性。
