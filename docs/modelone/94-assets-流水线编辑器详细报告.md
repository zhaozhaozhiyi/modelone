# 流水线编辑器“94 assets in total”详细说明

> 适用页面：截图中的 `new-pipeline-...` 流水线编辑器。
>
> 这份说明以当前仓库的前端实现、初始化任务模板和任务模板使用文档为依据。不同部署环境可能会增加、删除或升级模板，所以页面上实际显示的数量和参数应以当前接口返回为准。

## 1. 先说结论：这个页面是干什么的

这是一个**可视化机器学习/数据处理流水线编排器**。左侧是可拖拽的任务模板库，中间是画布，用户把左侧的组件拖到画布上，再用箭头连成上下游关系，最后保存并运行。

用大白话说，它把一串原本要手工执行的命令组织成一张“自动执行清单”：

```text
导入数据 → 清洗缺失值 → 特征变换 → 训练模型 → 评估模型 → 注册/部署模型
```

每一个方框就是一个任务（Task），每一条箭头就是“前一个任务成功后再执行后一个任务”。跑起来以后，系统会在集群容器中按顺序或并行执行，生成数据文件、模型文件、评估结果、日志、监控数据或在线服务。

## 2. “94 assets in total”到底是什么意思

`assets` 在这里不是图片素材，而是 **asset/task template（任务模板、流水线组件）**。

页面实现会从 `job_template_modelview` 接口取得任务模板，只统计 `version === "Release"` 的模板；当前初始化文件中一共有 96 个模板，其中 94 个是 Release，2 个是 Alpha，因此页面显示 94：

| 分类 | Release 数量 | 作用范围 |
|---|---:|---|
| 基础命令 | 3 | 自定义镜像、逻辑节点、Python 快速执行 |
| 数据导入导出 | 3 | DataX、数据集、模型导入 |
| 数据处理工具 | 3 | Hadoop、Volcano、Ray |
| 特征处理 | 21 | 清洗、变换、组合、降维、采样等 |
| 图像处理 | 8 | 图片质量、去噪、缩放、裁剪、增强等 |
| 视频处理 | 3 | 媒体下载、抽帧、抽音频 |
| 音频处理 | 3 | 音频增强、清洗、质量评估 |
| 文本处理 | 8 | OCR、清洗、过滤、隐私替换、问答数据生成 |
| 机器学习框架 | 1 | Ray-Sklearn 分布式训练/预测 |
| 机器学习算法 | 15 | LR、XGBoost、决策树、聚类、时间序列等 |
| 深度学习 | 5 | TensorFlow、PyTorch、Paddle、MindSpore、MXNet |
| 分布式加速 | 5 | Horovod、Megatron、DeepSpeed、ColossalAI、MPI |
| 模型处理 | 2 | 模型评估、模型格式转换 |
| 模型服务化 | 3 | 注册、离线推理、在线部署 |
| 机器视觉 | 1 | YOLOv8 目标检测 |
| 大模型 | 10 | 微调、奖励模型、强化学习、评估、量化、剪枝 |
| **合计** | **94** | **可直接用于流水线的发布版模板** |

初始化文件里另有 `one-hot` 和 `pca` 两个 Alpha 模板，它们不会计入这 94 个；对应能力已经在 `objective-process`、`dimension-reduction` 等 Release 组件中覆盖。

## 3. 左侧面板每个控件怎么用

### 3.1 搜索框：搜索模板名称或描述

输入中文、英文或模板 ID，例如 `缺失`、`xgb`、`图片`、`模型部署`。搜索会同时匹配模板名称和描述，并列出所属分类。点击搜索结果后，页面会自动展开对应分类，方便继续拖拽。

### 3.2 `94 assets in total`

这是当前接口返回的 Release 模板数量，不是当前画布上的节点数，也不是已经运行的任务数。它会随管理员新增、删除、发布模板而改变。

### 3.3 刷新按钮

重新请求模板列表。前端默认把任务模板缓存 24 小时；点击刷新可以立即重新加载，适合管理员刚发布模板、或模板参数发生变化后使用。

### 3.4 加号按钮

打开任务模板新增页面。它用于管理员把一个镜像、代码仓库、启动命令和参数定义注册成新的可拖拽组件。普通使用者通常只需要使用现有组件。

### 3.5 分类标题

例如“基础命令”“数据导入导出”“特征处理”。点击左侧小三角可以展开/收起分类。截图中“特征处理”处于展开状态，所以看到了 `union-join-data`、`drop-duplicates` 等卡片；其它分类目前收起，并不是没有内容。

### 3.6 组件卡片

卡片上方是模板名，下面是模板描述。鼠标悬停会显示创建人、镜像、版本、最后修改时间和配置文档（如果模板提供）。

使用方式：**按住卡片，拖到中间画布并松开**。松开时系统会创建一个任务节点，并按模板的默认值初始化参数。拖拽不是复制文字，而是实际在当前流水线中新增一个任务。

### 3.7 画布上的节点和连线

拖入后点击节点，会打开右侧任务配置板；可以改节点标签、内存、CPU、GPU、超时、重试次数、是否跳过以及模板参数。把一个节点底部的连接点拖到另一个节点顶部，可以建立依赖关系。节点的上游任务完成后，下游任务才会执行。

部分模板带有“推荐下游模板”信息，点击节点底部连接点会弹出推荐组件，可以快速接着搭建下一步。

## 4. 实际使用的标准步骤

1. 先打开或新建流水线，给流水线填写描述，选择项目组。
2. 在左侧搜索所需组件，展开分类。
3. 把组件拖到画布上；每拖一次就是一个新的任务节点。
4. 点击节点填写参数。常见必填项是输入路径、输出路径、列名、模型名、镜像、启动命令和 worker 数量。
5. 根据业务顺序连线；互不依赖的节点可以并行。
6. 配置每个节点的资源：CPU、内存、GPU、超时和重试次数。
7. 点击“保存”，确认右上角变成“已保存”。
8. 点击“运行”执行整条流水线；也可以在节点配置板中单独 debug 或 run。
9. 通过“日志”“容器”“定时记录”“监控”查看执行过程和资源使用情况。

默认情况下，新节点会带上 2G 内存、2 核 CPU、0 张 GPU、工作区 PVC 挂载到 `/mnt`，并使用 `cpu=true,train=true` 的节点选择器；正式任务应根据数据规模和模型大小调整资源。

## 5. 94 个 Release 组件逐项说明

下面每条都按“作用 → 怎么用 → 最终产出”写。路径一般指容器内路径，常见根目录是 `/mnt/{{creator}}/`；如果路径不一致，需要改成当前项目实际挂载路径。

### A. 基础命令（3 个）

1. **自定义镜像（custom image）**：用自己的 Docker 镜像执行任意程序。拖入后填写镜像、启动目录、启动命令，例如 `python train.py` 或 `bash run.sh`；适合已有代码、特殊依赖或临时调试。产出是命令产生的文件、模型、日志或服务进程。
2. **logical（逻辑节点）**：控制流程分支或下游是否继续。把它放在多个上游结果之后，配置逻辑判断代码；产出是成功/失败或条件信号，从而决定下游任务是否执行。
3. **python（Python 代码执行）**：直接运行几行到几十行的 Python，不必先制作镜像。填写代码和输入输出路径；适合轻量清洗、文件改名、统计或胶水逻辑。产出是代码写出的文件、变量结果和日志。

### B. 特征处理（21 个）

1. **drop-duplicates**：删除重复样本。填写输入数据路径和输出路径，可指定判重列；产出行数更少、重复记录被清理的数据集。
2. **drop-missing**：删除缺失率太高的特征列。输入数据、输出数据和缺失率阈值（例如 `0.3`）；产出列更可靠的数据集。
3. **drop-stablize**：删除几乎只有一个值的特征。输入数据、输出数据和稳定阈值（例如 `0.95`）；产出去掉低信息量字段的数据集。
4. **fill-missing**：填充缺失值。选择均值、 中位数或众数等策略并指定输入输出；产出没有或少有空值的数据集。
5. **calculate-metric**：计算非空数、均值、分位数、方差等统计量。指定输入路径和统计结果路径；产出一份特征质量/统计报表。
6. **outlier-detection**：检测异常值。选择标准差、箱线图、Tukey 或 Z-score，并决定是否删除；产出异常标记或清理后的数据集。
7. **calculate-correlation**：计算特征之间的相关性。输入特征数据并指定结果路径；产出相关系数矩阵或相似度结果，用于发现冗余特征。
8. **feature-combine**：组合已有字段生成衍生特征，例如金额×次数、年龄分段或多字段拼接。配置组合规则、输入和输出；产出新增衍生列的数据集。
9. **feature-importance**：评估特征重要性。选择随机森林、逻辑回归或 XGBoost 等方法，并提供标签列；产出特征重要性、IV、互信息或方差等排名结果。
10. **hadamard-multiply**：做逐元素乘法（同位置相乘），常用于两个等形状特征矩阵的门控、权重或交互。输入两个矩阵/数据文件；产出同形状的乘积矩阵。
11. **union-join-data**：合并数据，支持纵向 `union` 和按键横向 `join`。配置多个输入、连接键和输出路径；产出一张更完整的合并数据表。
12. **run-sql**：对数据执行 SQL。填写数据源、SQL 和结果路径；适合筛选、聚合、分组、关联和计算字段。产出 SQL 查询结果表。
13. **sort**：按一个或多个字段排序。指定排序列、升降序和输入输出；产出排序后的数据文件。
14. **index-process**：处理索引，包含增加索引、索引转列、列名重命名。填写索引文件、列映射和输出；产出列结构更规范的数据集。
15. **objective-process**：处理非数值类别字段。可用 Hash、标签编码、按频次编码、按目标统计编码或 one-hot 思路转换；产出适合模型输入的数值特征。
16. **data-tranform**：通用数值变换，包括 Box-Cox、二值化、DCT、函数转换、移动平均、类型转换、多项式展开。选择处理类型、列、参数和是否保留原列；产出变换后的新特征列。
17. **data-split**：拆分列、拆分行或做 SVD。配置列映射、行范围、输出目录或 SVD 输出目录；产出多个子数据集或分解后的矩阵文件。
18. **dimension-reduction**：降维，包含 PCA 和卡方筛选。设置目标列、保留维度/特征数和输出前缀；产出维度更低、训练更快的特征数据。
19. **sample**：采样，支持随机、加权、分层、过采样和欠采样（如 SMOTE）。设置比例、权重/分层文件或标签列；产出训练子集或类别更平衡的数据集。
20. **standardize-normalize**：做最大绝对值、Min-Max、StandardScaler、Normalizer、Z-score、时间列格式化等处理。选择列、方法和是否保留原列；产出尺度一致、适合模型训练的特征。
21. **discretization**：把连续变量离散成区间，支持等宽、等频、K-means/K-bins。设置列、箱数、策略和是否保留原列；产出类别/区间编码特征。

> 说明：`one-hot` 和 `pca` 在初始化数据里是 Alpha，因此不会出现在 94 的计数中；实际发布版分别可通过 `objective-process` 和 `dimension-reduction` 完成相同类型的工作。

### C. 数据导入导出（3 个）

1. **datax**：用 Alibaba DataX 在异构数据源之间同步。准备 DataX `job.json`，填写文件路径；产出目标库/目标文件中的同步数据。
2. **dataset**：从平台数据集模块导入指定数据集版本和分区。填写来源、名称、版本、分区和保存目录；产出挂载到流水线工作区的本地数据文件。
3. **model-download**：从模型管理或推理服务下载模型。填写模型名、子模型、版本、状态和保存目录；产出可被后续训练、转换或推理任务读取的模型文件。

### D. 数据处理工具（3 个）

1. **hadoop**：执行 HDFS、HBase、Sqoop、Spark 等大数据命令。填写实际集群可用的命令，例如 `hdfs dfs -ls /`；产出大数据侧的文件、表或处理结果。
2. **volcanojob**：提交有序的多机分布式任务。填写 worker 镜像、工作目录、启动命令和机器数；产出分布式脚本生成的文件、模型或统计结果。
3. **ray**：运行 Python 多机分布式任务。填写 Ray 镜像、工作目录、初始化脚本、启动命令和 worker 数；产出多机并行计算结果。

### E. 机器学习框架（1 个）

1. **ray-sklearn**：用 Ray 分布式运行 sklearn 模型训练和预测。填写训练 CSV、特征列、标签列、模型名、模型参数、模型文件路径，可选预测文件和 worker 数；产出 `joblib` 模型和预测结果 CSV。

### F. 机器学习算法（15 个）

这些组件的共同用法是：准备训练数据、指定特征列和标签列，填写算法参数与模型保存路径，拖入流水线后连接数据准备节点；产出训练模型、评估指标和（若配置预测）预测结果。

1. **adaboost**：提升树/弱学习器集成，适合分类或回归基线。
2. **xgb**：单机 XGBoost，适合表格数据的高效果分类/回归。
3. **bayesian**：贝叶斯类算法，适合概率建模或朴素贝叶斯类任务。
4. **decision-tree**：决策树，容易解释，适合分类和回归。
5. **gbdt**：梯度提升决策树，适合结构化数据。
6. **hyperparam-search-ray**：使用 Ray 并行搜索超参数，设置搜索空间、目标指标和试验数量；产出最优参数和最佳模型。
7. **hyperparam-search-nni**：使用 NNI 做超参搜索/实验管理；产出试验记录、最优配置和模型。
8. **kmean**：K-Means 聚类，不需要标签；产出簇中心和每条样本的聚类编号。
9. **knn**：K 近邻分类/回归；设置邻居数等参数，产出预测标签/数值。
10. **lightgbm**：LightGBM 梯度提升树，适合大规模表格数据。
11. **lr**：逻辑回归，适合二分类/多分类并且需要可解释系数的场景。
12. **random-forest**：随机森林分类或通用树集成；产出模型和特征重要性。
13. **random-forest-regression**：随机森林回归，目标是连续数值。
14. **arima**：ARIMA 时间序列预测；需要按时间整理的目标序列，产出未来时间点预测。
15. **ar**：自回归时间序列模型；用过去若干时刻预测当前/未来值。

### G. 深度学习（5 个）

1. **tfjob**：提交 TensorFlow 分布式训练；填写 worker 镜像、工作目录、启动命令和 worker 数，产出 TensorFlow checkpoint/模型。
2. **pytorchjob**：提交 PyTorch 分布式训练；常见启动命令是 `bash start.sh`，产出 checkpoint、模型和训练日志。
3. **paddlejob**：提交 Paddle 分布式训练；准备 Paddle 代码和镜像，产出 Paddle 模型或 checkpoint。
4. **mindspore**：提交 MindSpore 分布式训练；准备 MindSpore 脚本和设备资源，产出 MindSpore 模型。
5. **mxnet**：提交 MXNet 分布式训练；准备 MXNet 代码、数据和 worker，产出 MXNet 模型/参数。

### H. 分布式加速（5 个）

1. **horovod**：用 Horovod 做多 GPU/多机数据并行；产出加速后的训练模型。
2. **megatron**：用 Megatron 训练大规模 Transformer；需要多 GPU、训练语料和并行配置，产出大模型 checkpoint。
3. **deepspeed**：用 DeepSpeed 做显存优化、数据/流水线并行；产出训练 checkpoint 或最终模型。
4. **colossalai**：用 Colossal-AI 做大模型并行和显存优化；产出训练模型及日志。
5. **mpi**：用 MPI 启动多进程/多机计算；适合已有 MPI 程序，产出程序生成的计算结果或模型。

### I. 模型处理（2 个）

1. **model-evaluation**：评估模型效果。接入模型和测试数据，设置指标；产出 accuracy、AUC、F1、损失等评估报告。
2. **model-convert**：转换模型格式，例如转换到 ONNX/推理框架可用格式。填写源模型、目标格式和输出目录；产出新的模型文件。

### J. 模型服务化（3 个）

1. **model-register**：把训练好的模型登记进模型管理。填写项目组、模型名、版本、路径、指标、框架和推理框架；产出一个可追踪、可复用的模型版本。
2. **model-offline-predict**：做分布式离线推理。填写推理镜像、工作目录、启动命令和 worker 数；产出批量预测文件。
3. **deploy-service**：部署在线推理服务。填写模型信息、服务镜像、启动命令、端口、副本数、CPU/内存/GPU、健康检查和指标接口；产出可访问的 HTTP 推理服务地址。

### K. 视频处理（3 个）

1. **media-download**：分布式下载媒体。准备文本配置，每行写 URL 和本地目标路径；产出下载到工作区的视频、图片或音频文件。
2. **video-img**：分布式视频抽帧。配置视频路径、目标图片目录和帧率；产出按帧率抽取的图片序列。
3. **video-audio**：从视频中分布式提取音频。配置视频路径和音频目标路径；产出 WAV/MP3 等音频文件。

### L. 机器视觉（1 个）

1. **yolov8**：YOLOv8 目标检测训练。填写训练/验证列表、类别、batch、epoch、预训练权重和模型保存路径；产出最佳权重、检测指标和可用于推理的 YOLO 模型。

### M. 文本处理（8 个）

1. **paddleocr-vl**：从 PDF、图片或文档中提取文字/版面内容；产出 Markdown、结构化文本或文档内容。
2. **nlp-clean-data**：清洗异常文本、空文本、乱码、格式错误等；产出更干净的文本数据集。
3. **nlp-filter-data**：按规则或质量条件过滤异常文档；产出通过筛选的文档集合。
4. **nlp-replace-private-data**：识别并替换姓名、手机号、身份证等隐私信息；产出脱敏文本。
5. **nlp-analyze-data**：统计文本数量、长度、语言/质量分布等；产出文本质量分析报表。
6. **question-generation**：根据文本生成问题；产出问题列表或问题数据集。
7. **question-answer-generation**：从文本生成问答对；产出可用于训练/评估的问答数据。
8. **question-answer-extension**：扩充已有问答对，生成改写、同义问法或更多样本；产出更大的问答训练集。

### N. 图像处理（8 个）

1. **vision-quality-assessment**：评估图片清晰度、尺寸、亮度、损坏等质量；产出质量分数和问题清单。
2. **vision-image-blur**：图片去噪/去模糊；产出更清晰或噪声更低的图片。
3. **vision-image-resize**：统一图片尺寸或缩放比例；产出尺寸规范的图片集。
4. **vision-image-normalize**：按均值/方差等做像素标准化；产出适合模型输入的图片。
5. **vision-image-cropping**：按坐标、中心或目标区域裁剪；产出裁剪后的局部图片。
6. **vision-image-equalize**：直方图均衡化、增强对比度；产出亮度/对比度更适合识别的图片。
7. **vision-image-cvtcolor**：转换颜色空间，例如 RGB、BGR、灰度、HSV；产出目标颜色空间的图片。
8. **vision-image-augmentation**：旋转、翻转、平移、缩放等图像增强；产出数量更多、变化更多的训练图片。

### O. 音频处理（3 个）

1. **audio-augment**：音频增强，例如加噪、变速、变调或切片；产出更丰富的训练音频。
2. **audio-clean**：去除静音、噪声、异常片段或格式问题；产出更干净的音频数据集。
3. **audio-quality-assessment**：评估音频时长、采样率、响度、噪声或损坏情况；产出质量统计和问题清单。

### P. 大模型（10 个）

1. **deepseek**：DeepSeek 系列模型微调；准备基座模型、训练数据和 GPU 资源，产出微调后的 checkpoint/模型。
2. **llama-factory-sft**：用 LLaMA-Factory 做监督微调（SFT）；准备 instruction/input/output 数据，产出指令跟随模型。
3. **llama-factory-reward**：训练奖励模型；准备偏好/排序数据，产出用于 RLHF 的 reward model。
4. **llama-factory-ppo**：用 PPO 做大模型强化学习；准备策略模型、奖励模型和训练配置，产出强化学习后的模型。
5. **llama-factory-eval**：用 LLaMA-Factory 评估模型；填写模型、数据集和评估配置，产出指标、样例回答和评估日志。
6. **opencompass**：用 OpenCompass 做大模型基准评测；配置模型和评测集，产出多任务基准分数和报告。
7. **llm-safety-eval**：做大模型安全评估；配置安全测试集和模型，产出越权、毒性、隐私、拒答等安全指标。
8. **llm-benchmark**：做大模型性能基准测试；配置模型、任务和资源，产出准确率、吞吐、延迟、显存等结果。
9. **llm-quantization**：量化大模型，降低显存和推理成本；选择量化方法、位数和模型路径，产出量化模型。
10. **llm-prune**：剪枝大模型，减少参数或计算量；设置剪枝策略和比例，产出剪枝后的模型及效果对比。

## 7. 最终能产出什么

根据所选组件，最终产物可能是：

- 清洗、合并、排序、采样后的 CSV/Parquet/JSON 数据集；
- 统计报表、相关性矩阵、特征重要性排名和异常样本清单；
- 训练好的传统机器学习模型、深度学习 checkpoint、YOLO 权重或大模型 checkpoint；
- ONNX/推理格式/量化/剪枝后的模型文件；
- 批量离线预测结果；
- 注册到模型管理的版本化模型；
- 可通过 HTTP 访问的在线推理服务；
- OCR Markdown、脱敏文本、问题集、问答集；
- 处理后的图片、视频帧、音频和质量评估报告；
- 完整的流水线运行记录、日志和资源监控数据。

最典型的最终效果是：用户只需要点击一次“运行”，平台就会自动完成“数据准备 → 特征工程 → 模型训练 → 模型评估 → 注册/部署”，并且每一步都有日志、重试、资源限制和历史记录可查。

## 8. 使用时最容易踩的坑

1. **路径必须是容器可见的路径**：本机路径不一定能被任务容器读取，通常要放在平台数据集或挂载的 `/mnt` 目录。
2. **上一步的输出路径要和下一步的输入路径一致**：连线只表达执行顺序，不会自动替你猜文件名。
3. **模板参数以右侧配置板为准**：管理员更新模板后，参数可能变化；先刷新左侧模板列表。
4. **资源不足会导致排队或失败**：GPU 任务要填 GPU 数量/型号，分布式任务要确认 worker 数和集群配额。
5. **先单节点 debug 再整链运行**：这样能较快确认镜像、路径、依赖和命令都正确。
6. **Alpha 模板不应作为生产能力判断依据**：截图的 94 是 Release 可用数，Alpha 模板可能需要管理员先发布。
