# ModelOne 品牌定义与 UI 视觉规范

**版本：** 0.1（提案）
**适用范围：** Web 控制台、模型市场、开发者文档、部署交付物与对外传播
**品牌状态：** ModelOne 为对外品牌候选名；CubeStudio 暂保留为项目代号与兼容标识

## 0. 执行摘要

### 品牌定义

> **ModelOne｜企业级 AI 生产平台**<br>
> 统一算力、模型与应用交付。

ModelOne 面向拥有自有数据、算力和模型资产的企业与组织，提供从数据准备、在线开发、训练评测、模型注册、推理服务到智能应用交付的一体化平台。平台的差异化不是“又一个大模型工作台”，而是把异构算力、模型工程和企业治理放到同一个可控的生产系统中。

### 品牌本质

**让 AI 从实验进入生产。**

### 三个价值支柱

1. **算力统一**：统一纳管 CPU、GPU、NPU、多集群与边缘资源，降低异构基础设施的使用门槛。
2. **模型贯通**：连接数据、标注、开发、训练、评测、注册、部署和推理服务，减少工具与环境之间的断点。
3. **企业可控**：支持私有化、离线部署、多租户、权限、计量、审计和国产异构算力，满足生产环境的安全与治理要求。

## 1. 品类与定位

### 推荐品类

**企业级 AI 生产平台（Enterprise AI Production Platform）**

这个品类比“AI 平台”“MLOps 平台”更能表达平台的实际价值：不仅帮助团队开发模型，还负责把模型稳定、可观测、可治理地交付到业务系统。

### 定位陈述

> 对需要在自有数据与算力上规模化落地 AI 的企业团队，ModelOne 是一个企业级 AI 生产平台。它统一异构算力，贯通数据到模型服务的全链路，并提供私有化、可治理的生产能力，让算法团队更快把模型变成稳定可用的业务能力。

### 目标用户

| 用户 | 核心任务 | ModelOne 应该让他感受到 |
| --- | --- | --- |
| AI 平台负责人 / CTO | 建设统一平台、控制成本与风险 | 资源、权限、成本和交付状态可控 |
| 算法工程师 | 开发、训练、评测和迭代模型 | 环境少配置，实验可以顺畅进入服务 |
| 算力 / 运维工程师 | 管理多集群、GPU/NPU、存储与监控 | 异构资源有统一视图，故障有明确动作 |
| 应用开发者 | 调用模型、接入网关、构建智能应用 | 模型有稳定 API，版本和流量可治理 |
| 行业交付团队 | 私有化、离线、信创环境交付 | 交付边界清楚，平台可复制、可审计 |

### 核心使用场景

- 企业内网建设统一 AI 研发与推理平台。
- 多种 GPU/NPU 并存时的算力调度、共享与成本控制。
- 从数据处理、标注、训练、评测到模型上线的持续迭代。
- 大模型微调、量化、评测、多机推理和统一模型网关。
- 模型市场、智能体和私有知识库的快速交付。

## 2. 品牌个性与语言

### 品牌个性

**可靠、清晰、开放、克制。**

- **可靠**：先显示状态、风险和边界，再强调能力。
- **清晰**：用用户任务命名功能，少用内部实现术语。
- **开放**：兼容主流框架、模型、芯片和存储，不把用户锁进单一生态。
- **克制**：界面为操作和判断服务，不用装饰掩盖复杂度。

### 语气规则

| 场景 | 推荐表达 | 避免表达 |
| --- | --- | --- |
| 产品介绍 | 统一异构算力，贯通模型交付 | 重新定义 AI 未来 |
| 功能说明 | 将模型发布为可观测的在线服务 | 一键开启无限可能 |
| 错误反馈 | 训练任务未启动：资源组没有可用 GPU | 出错了，请稍后再试 |
| 成功反馈 | 模型 v2 已发布到测试环境 | 太棒了，部署成功！ |
| 能力宣传 | 支持私有化、离线和国产异构算力 | 全面领先、行业第一 |

### 一句话介绍

**ModelOne 把企业的算力、数据、模型和应用交付放进一套可治理的生产系统。**

### 对外短文案

**主标题：** 让 AI 从实验进入生产
**副标题：** ModelOne 统一异构算力，贯通数据、训练、推理与智能应用交付。

## 3. 品牌命名与产品架构

### 名称用法

- 英文标准写法：`ModelOne`，M 与 O 大写，不写成 `Model One`、`modelone` 或 `MODELONE`。
- 中文品类写法：`ModelOne 企业级 AI 生产平台`。
- 首次出现使用完整名称，后续可简称 `ModelOne` 或“平台”。
- `CubeStudio` 在迁移期间只作为项目代号、仓库标识、兼容路径和历史版本说明，不再作为新界面的主品牌。

### 产品线命名

| 产品线 | 覆盖能力 | 控制台导航建议 |
| --- | --- | --- |
| **ModelOne Compute** | 集群、节点、GPU/NPU、vGPU、RDMA、资源组、计量 | 算力 |
| **ModelOne Data** | 数据集、SQL、ETL、标注、数据资产 | 数据 |
| **ModelOne Build** | Notebook、镜像、任务模板、Pipeline | 开发与编排 |
| **ModelOne Train** | 训练、分布式任务、超参搜索、评测、模型注册 | 训练 |
| **ModelOne Serve** | 推理服务、模型版本、网关、流量与弹性 | 服务 |
| **ModelOne Hub** | 模型、算子、应用、智能体与知识库 | 模型与应用 |

产品线名称是信息架构标签，不要求每个页面都显示英文后缀。主导航优先使用中文任务名称，英文只用于 URL、API、文档和开发者场景。

## 4. 视觉概念：墨黑作业台 Ink Production

ModelOne 的视觉母题是**墨黑作业台**：墨黑是稳定的基础设施，灰阶负责层级、边界和选中状态，浅色表面承载密集的生产信息。它表达“状态清楚、动作明确、系统可靠”，也与通用科技蓝和大面积渐变区分开。

### 视觉关键词

**精确、坚实、明亮、可观测、少装饰。**

### Logo 系统

Logo 采用三面等距魔方：黄色代表算力与能量，青色代表模型流转，珊瑚色代表应用交付，石墨色负责轮廓与“1”的中轴。Logo 允许使用三色，这是品牌识别的例外；控制台 UI 使用墨黑作为主品牌动作色，Logo 的青色、黄色和珊瑚色不得直接扩散为业务状态色。

首版资源位于 `myapp/frontend/src/images/`：

- `modelone-logo.svg`：浅色背景横版主标。
- `modelone-logo-reverse.svg`：石墨色背景横版反白标。
- `modelone-mark.svg`：独立魔方图标，用于加载态、favicon 和紧凑导航。

Logo 不使用渐变、六色小方格或复杂阴影；在 16px 图标尺寸下应保留三个面和清晰的中轴。

### 禁用方向

- 不使用紫蓝渐变、发光网格、粒子背景、悬浮光球等泛 AI 装饰。
- 不把 Logo 的彩色面扩散成业务装饰或状态色；警告必须使用独立语义色，并同时显示图标与文字。
- 不用大面积插画或营销卡片替代真实的任务、资源和模型信息。

## 5. UI 设计令牌

令牌命名按用途，不按色相命名。项目通过 `myapp/frontend/src/brand-tokens.less` 集中定义令牌，再由 Ant Design 主题和业务页面引用。下面的颜色是第一版基准，落地时应通过对比度检查。

### 颜色

#### 品牌与交互

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--mo-brand-primary` | `#17191D` | 品牌主色、主操作填充、选中导轨 |
| `--mo-brand-primary-hover` | `#262A31` | 主操作悬停 |
| `--mo-brand-primary-active` | `#0E1013` | 主操作按下 |
| `--mo-brand-primary-soft` | `#E9EAEC` | 选中背景、浅色提示 |
| `--mo-ink` | `#17191D` | 主文字、导航底色 |
| `--mo-brand-text` | `#17191D` | 浅色背景上的品牌强调文字 |
| `--mo-brand-contrast` | `#FFFFFF` | 墨黑主操作上的文字与图标 |

墨黑与白色的对比度约为 17.4:1；主操作使用墨黑背景 + 白色文字，浅色选中态使用灰阶背景 + 墨黑文字。

#### 中性色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--mo-bg` | `#F5F6F7` | 应用背景 |
| `--mo-surface` | `#FFFFFF` | 页面、表格、表单和抽屉表面 |
| `--mo-surface-muted` | `#F0F2F4` | 次级区域、禁用背景 |
| `--mo-text-secondary` | `#50545C` | 辅助文本 |
| `--mo-text-tertiary` | `#737985` | 提示和元信息 |
| `--mo-border` | `#D9DCE1` | 默认边框与分隔线 |
| `--mo-border-strong` | `#B8BDC6` | 强边框、输入焦点前的结构线 |

#### 语义色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--mo-success` | `#16825D` | 成功、健康、已发布 |
| `--mo-warning` | `#A65F00` | 警告、资源紧张、即将过期 |
| `--mo-danger` | `#C7353C` | 失败、删除、不可恢复操作 |
| `--mo-info` | `#1769AA` | 信息、帮助、进行中 |

语义色必须配合图标、文字或状态标签使用，不能只靠颜色表达状态。

### 字体

为适配内网离线部署，不默认依赖远程字体。推荐字体栈：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
font-variant-numeric: tabular-nums;
```

代码、资源 ID、版本号和指标值使用：

```css
font-family: "IBM Plex Mono", "SFMono-Regular", Consolas, monospace;
```

只使用三个字重：400（正文）、500（标签与导航）、600（标题与主操作）。不使用 700 以上字重堆叠层级。

| 角色 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| Page title | 24 / 32 | 页面标题 |
| Section title | 18 / 26 | 区块标题 |
| Component title | 16 / 24 | 卡片、表格、抽屉标题 |
| Body | 14 / 22 | 默认界面文本 |
| Small | 13 / 20 | 辅助信息、表格次级列 |
| Caption | 12 / 18 | 时间、来源、状态元信息 |

正文和 UI 标签的字间距保持 `0`；英文全大写标签使用 `0.06em` 至 `0.1em`；标题不使用大幅负字间距。

### 间距、圆角与阴影

- 基础网格：4px；常用间距：4 / 8 / 12 / 16 / 24 / 32px。
- 页面左右内边距：桌面 24px，窄屏 16px。
- 控件高度：小 28px、默认 32px、大 40px。
- 默认圆角 4px；弹窗、抽屉和大面板最多 8px；不使用胶囊化的业务容器。
- 默认使用 1px 边框建立结构，阴影只用于弹层、菜单和悬浮对象。
- 表格行高建议 44px；资源监控和日志类表格允许压缩到 36px，但必须保留可读性。

## 6. 布局与信息层级

### 应用框架

- 顶部导航：56px，深色 `--mo-ink`，左侧放 ModelOne 标识和当前工作区。
- 侧边导航：展开 232px，收起 64px；一级导航按任务域组织，不按技术组件组织。
- 内容区：背景使用 `--mo-bg`，页面标题固定在内容顶部，操作按钮紧邻标题右侧。
- 重要页面采用“标题区 → 筛选 / 操作区 → 主数据区 → 辅助信息”的顺序。
- 资源、任务和服务页面优先使用表格、时间线和状态面板，减少无意义的卡片墙。

### 导航分组建议

1. 工作台
2. 算力
3. 数据
4. 开发与编排
5. 训练与评测
6. 模型与服务
7. 模型与应用
8. 监控与治理
9. 管理设置

导航标签使用用户任务语言；例如“推理服务”可以保留为页面名，但一级导航建议归入“模型与服务”。

## 7. 核心组件规则

### 按钮

- 主操作：墨黑背景 + 白色文字，同一视图最多一个主操作。
- 次操作：白色背景 + 中性边框。
- 危险操作：危险色描边或实心，不使用品牌黄表达删除或停止。
- 图标按钮必须提供 tooltip 和可访问名称；有明确动作时优先使用熟悉图标。
- 加载中的按钮保留原文字，显示 spinner，并阻止重复提交。

### 表格

- 表头使用 `--mo-surface-muted`，文本 13px / 500，避免全大写。
- 状态列使用“图标 + 文本 + 可选颜色”，如“● 运行中”“✓ 已完成”。
- 操作列固定在右侧，最多显示一个主操作，其余进入更多菜单。
- 必须定义加载、空数据、无搜索结果、请求失败和大数据量状态。
- 长名称、镜像地址、模型版本和任务 ID 使用截断 + tooltip，不撑开表格。

### 卡片与面板

- 卡片只承载一个清晰对象或任务，不在卡片内部继续嵌套卡片。
- 资源指标优先用数字、单位、趋势和更新时间表达，不用装饰性环形图堆满页面。
- 面板标题要能回答“这里管理什么”，不要只写“概览”“信息”。

### 标签与状态

状态标签统一使用：`准备中 / 排队中 / 运行中 / 成功 / 失败 / 已停止 / 已过期`。

- 准备中：中性灰
- 排队中：信息蓝
- 运行中：品牌黄或信息蓝，配合进行中图标
- 成功：成功绿
- 失败：危险红
- 已停止 / 已过期：中性灰或警告橙

### 表单

- 标签放在字段上方，说明文字紧随字段，不依赖 placeholder 传递关键信息。
- 校验在失焦后触发；提交后将焦点移至第一处错误。
- 服务端失败必须保留用户已填写内容，并提供可复制的错误 ID。
- 资源规格、模型版本、集群和项目组等字段显示当前可用范围，不让用户提交后才发现资源不可用。

## 8. 关键页面的视觉优先级

### 工作台

第一视线显示：当前项目、可用算力、运行中任务、异常告警和最近模型发布。把“新建 Pipeline”作为主操作，把教程和视频放到次级区域。

### 算力

第一视线显示：集群健康、GPU/NPU 使用率、排队任务、资源组配额和成本。资源卡片不应只显示总量，必须同时显示申请量、使用量和更新时间。

### Pipeline / 训练

画布使用中性背景和细网格；节点按数据、处理、训练、评测、发布分组，用颜色表达类型而不是状态。运行状态由边框、图标和进度共同表达。

### 模型与服务

模型列表以版本、指标、环境、部署状态和最后更新时间为核心信息。发布、回滚、灰度和下线必须使用明确的确认层级，避免把危险动作放在同一组主按钮中。

### 监控

优先使用时间序列、表格和告警列表。每个图表显示时间范围、采样粒度、数据更新时间和空数据原因；不使用没有单位的装饰性数字。

## 9. 状态与可访问性基线

所有取数、计算、提交和发布类界面必须覆盖以下状态：

- **Loading**：骨架或明确的加载指示，超过 15 秒显示“仍在加载，可取消或稍后重试”。
- **Empty**：说明为什么为空，并给出下一步动作。
- **Error**：说明发生了什么、可能原因和恢复动作。
- **Populated**：默认成功路径。
- **Edge**：长名称、超大数据量、缺失可选字段和部分网络失败。

交互基线：键盘可达、焦点可见、正文对比度至少 4.5:1、UI 边界至少 3:1；toast 使用 `role="status"`，错误使用 `role="alert"`，重要对话框使用 `role="alertdialog"`。

## 10. 对现有前端的落地顺序

仓库当前已经有主题入口，但 `theme.ts` 仍以 `#1E1653`、`#1672fa` 为主要主题色，`atom.less` 和部分页面样式存在大量直接写入的颜色值。建议按下面顺序迁移：

### 第一期：品牌基础层

1. 新增 `brand-tokens.less`，集中定义品牌、中性色和语义色。
2. 将 `global.config.ts` 的展示标识切换为 ModelOne，同时保留历史 logo 和资源路径的兼容别名。
3. 将 `theme.ts` 的主题入口改为 ModelOne 默认主题，明确墨黑主操作与白色文字的对比关系。
4. 更新 `public/index.html`、404 页、加载页、页面标题和 favicon 的展示名称。

### 第二期：全局框架层

1. 更新 `index.less` 的导航、页面背景、边框、正文和链接令牌。
2. 重做顶部导航、侧边导航、当前模块标签和用户菜单的状态样式。
3. 将 `atom.less` 中的 `@common_blue`、`@success_green` 等语义不清的别名迁移为用途令牌。

### 第三期：高频工作流

按“工作台 → Pipeline → 训练 → 模型管理 → 推理服务 → 算力监控”的顺序处理页面。每处理一个页面，必须同时补齐加载、空、错误、禁用和长文本状态。

### 第四期：清理与兼容

- 将业务页面中的直接十六进制颜色替换为令牌。
- 保留 API、数据库 app 标识、镜像仓库路径和已有 URL 的兼容，不把品牌改名和代码仓库重命名绑定在同一发布中。
- 在文档、示例 pipeline 和 SDK 中增加“ModelOne（原 CubeStudio）”过渡说明，待一个完整版本周期后再移除旧称。

## 11. 验收标准

品牌与 UI 规范进入实现前，至少通过以下检查：

- 新用户能从首页和导航理解“算力、模型、服务”三条主线。
- 品牌主色统一使用墨黑，Logo 彩色面不扩散到业务 UI，状态色不与品牌色混用。
- 页面正文和主要控件达到可读对比度，墨黑主操作使用白色文字。
- 所有表格、表单、列表和监控面板具备加载、空、错误、成功和边界状态。
- 1440px、1024px、768px 和 390px 宽度下，导航、表格、按钮和长名称不重叠、不溢出。
