### 1.3 产品定位

平台为企业级一站式 AI 生产平台，面向企业内部的项目、数据、算力、开发环境、训练流程、模型、推理服务和智能应用，提供从数据准备到模型交付的可治理工作台。仓库仍以 CubeStudio 作为项目和兼容标识，产品对外名称可采用 ModelOne，名称不影响现有 API、数据库和部署兼容性。

## 2. 建设目标与范围

### 2.1 建设目标

1. 为用户提供按项目空间隔离的 AI 开发与交付环境。
2. 统一管理 Kubernetes 集群中的 Notebook、任务、工作流、服务和推理服务。
3. 支持数据集、元数据、数据维表及 SQL 查询等数据资产操作。
4. 通过 Pipeline 和任务模板把代码、镜像、资源规格和运行参数编排为可重复执行的流程。
5. 对训练模型进行登记、下载、部署和版本追踪。
6. 提供在线推理、AIHub 模型市场和可配置对话应用。
7. 对用户访问、资源运行、Pod 日志、操作日志和异常状态提供可观测能力。

### 2.2 系统范围

**本系统包含：** Web 控制台、后端 REST/页面 API、关系型元数据库、Kubernetes 资源编排、异步任务调度、对象/共享存储引用、模型与服务管理。

**本系统不直接包含或需外部提供：** Kubernetes 集群本身、容器镜像仓库、具体训练框架、外部数据库/数据源、Grafana 或其他监控系统、第三方身份源、外部大模型接口、企业消息渠道。平台通过配置和接口接入这些组件。

### 2.3 不确定范围

README 还宣称多租户计费、算力租赁、自动标注、多种国产芯片、大模型微调、知识库、智能体、边缘计算等扩展能力。当前仓库存在部分字段、配置或导航入口，但未能逐项确认完整闭环，均列入第 13 节待确认清单。

## 3. 用户与角色

### 3.1 用户类型

| 角色 | 主要职责 | 主要使用范围 |
| --- | --- | --- |
| 平台管理员 | 管理用户、角色、菜单、集群、资源和全局配置 | 全局治理、监控、审计、外部链接 |
| 项目创建者（creator） | 创建/维护项目组，管理组成员和组内资源 | 项目组、成员、Pipeline、服务和数据 |
| 项目开发者（dev） | 开发 Notebook、镜像、任务、Pipeline 和模型 | 项目内研发操作 |
| 项目运维者（ops） | 运行、停止、清理任务和服务，查看日志与监控 | 项目内运行运维 |
| 普通平台用户 | 使用被授权的项目、数据、模型和应用 | 只读或受限操作 |
| 外部 API 调用方 | 通过认证 Header/服务 API 调用平台能力 | 模型/对话/查询接口 |

### 3.2 权限规则

- 所有受保护请求要求已登录用户；未登录请求返回 401，并跳转登录流程。**C**
- 支持账号密码登录，支持通过 `Authorization` Header 加载用户。**C**
- Flask-AppBuilder 角色与权限控制菜单、视图、API 和动作；管理员可见用户、角色、日志和管理员链接。**C**
- 用户可关联多个项目组；项目组成员角色为 `dev`、`ops`、`creator`，且同一用户在同一项目唯一。**C**
- 项目和资源操作必须校验创建者、项目成员角色或 API 权限；无权限的编辑、删除操作应失败并返回提示。**C/I**
- 数据集、对话、模型市场等对象可以通过 `owner` 字段配置所有者或公开可见范围。**C**
- 正式需求应补充：角色权限矩阵、跨项目访问规则、管理员与项目创建者的边界、API Token 生命周期。**T**

## 4. 总体架构与运行约束

### 4.1 逻辑架构

```text
浏览器 React 控制台
        │ 动态菜单、页面路由、Axios REST 调用
        ▼
Flask-AppBuilder / Flask API 层
        ├─ 身份认证、RBAC、CSRF、CORS、国际化
        ├─ 通用 REST CRUD、筛选、分页、导入导出、图表
        ├─ 项目/数据/开发/训练/服务/AI 应用领域接口
        └─ 日志、审计、消息提示
        ├───────────────┬────────────────┐
        ▼               ▼                ▼
关系型元数据库     Kubernetes 集群     Celery/异步任务
用户、项目、模型     Pod、Service、CRD     调度、轮询、清理
        │               │                │
        └────── 外部镜像仓库、存储、监控、模型接口 ──────┘
```

### 4.2 技术与部署约束

- 后端：Python Flask + Flask-AppBuilder + SQLAlchemy/Alembic。**C**
- 前端：React 17、TypeScript、Ant Design；菜单从后端 `/myapp/menu` 动态生成。**C**
- 运行资源：Kubernetes 多集群配置，以项目选择的集群、命名空间和节点选择器创建资源。**C**
- 异步能力：Celery 配置用于调度、轮询和后台任务。**C/I**
- 元数据库：通过 SQLAlchemy URI 配置，具体数据库类型和生产高可用方案需部署配置确定。**C/T**
- 健康检查：至少提供 `/health`、`/healthcheck`、`/ping`。**C**
- 默认应用入口重定向到 `/frontend/`，前端构建产物由应用提供。**C**
- 应支持 HTTP/HTTPS、反向代理、跨域、压缩和可选安全响应头；具体安全基线由部署环境确定。**C/I**

## 5. 功能需求

### 5.1 工作台与导航

**FR-001 动态导航（C）**

- 系统应根据当前用户返回顶部导航、左侧导航、子菜单和关联页面。
- 菜单至少覆盖：项目空间、数据资产、开发/编排、训练/实验、模型/服务、AIHub/应用和管理员设置；实际名称由配置和国际化决定。
- 菜单项支持 API 页面、iframe、内部路由和外链四种跳转方式。
- 系统应根据用户权限隐藏或禁用无权菜单。

**FR-002 用户工作台（C/I）**

- 展示当前用户可访问的项目、任务、服务和常用入口。
- 支持顶部文档、问题反馈、模型市场等可配置链接。
- 支持页面级弹窗/公告配置。

### 5.2 身份、用户与项目空间

**FR-010 身份认证（C）**

- 支持登录、退出、注册入口和登录超时处理。
- 前端请求无用户 Cookie 时跳转登录；后端无用户或无效 Header 时返回 401。
- 用户信息包括用户名、昵称、邮箱、组织、角色、激活状态、登录统计和平台秘钥。
- 支持扩展远程用户/单点登录，具体协议由自定义安全管理器配置。**I/T**

**FR-011 角色与权限（C）**

- 管理角色、视图菜单、模型 API 和动作权限。
- 记录访问动作、HTTP 方法、路径、状态、请求摘要、耗时和来源。
- 管理员可查询和清理操作日志。

**FR-012 项目空间（C）**

- 创建、编辑、查看和删除项目组；项目包含名称、描述、类型和扩展配置。
- 项目可绑定集群、组织、命名空间策略、默认节点选择器和持久化挂载。
- 项目至少区分 Notebook、Pipeline、Service、AutoML 等命名空间用途。
- 项目可维护成员及成员角色、资源配额、可用资源组。
- 项目删除必须校验关联资源和操作者权限，删除策略需在正式需求中确认。**C/T**

### 5.3 数据资产

**FR-020 数据集管理（C）**

- 支持创建、编辑、查看、筛选、分页、上传、下载、预览和删除数据集。
- 数据集记录名称、版本、子集、切分、领域、行业、用途、文件类型、来源、路径、下载地址、大小、条目数、时长、状态、负责人和扩展信息。
- 支持图片、音频、文本、表格等文件类型的元信息登记；实际内容处理能力由存储和算子配置决定。
- 支持将数据集保存到配置的持久化存储，并返回预览或下载地址。

**FR-021 数据地图与元数据（C）**

- 管理库表元数据，包括产品、数据库、数据域、负责人、安全等级、价值评分、存储大小、数仓等级、成本、生命周期和建表 DDL。
- 管理字段信息，包括列名、描述、字段类型、备注和分区类型。
- 支持元数据导入/上传、批量删除和列表筛选。

**FR-022 维表/外部表（C）**

- 维护 SQLAlchemy 连接串、表名、中文标签、描述、应用、责任人、字段信息和状态。
- 支持查询远程表、创建外部表、补充表信息、模板下载/上传、数据下载和批量操作。

**FR-023 SQL Lab（C）**

- 用户可提交 SQL 查询任务，选择计算引擎并填写引擎参数。
- 系统应展示提交、开始、结束时间、任务阶段、状态、执行日志、UI 地址、结果地址、结果行数和错误信息。
- 支持查询状态、获取结果、下载结果和停止任务。
- 支持的具体引擎由部署配置决定，不能仅依据 README 视为全部可用。**T**

### 5.4 镜像与在线开发

**FR-030 镜像仓库（C）**

- 管理镜像仓库地址、账户、密码和 Kubernetes 拉取秘钥。
- 管理镜像名称、分类、描述、入口点、Dockerfile、Git 路径和所属仓库。
- 镜像敏感字段必须脱敏展示并采用安全存储；当前代码的加密和轮换方案需确认。**I/T**

**FR-031 在线构建镜像（C）**

- 用户可基于项目、命名空间、基础镜像和构建参数创建构建任务。
- 支持 GPU 需求、连续构建、调试、保存结果镜像和清理构建 Pod。
- 构建过程应可查看状态、日志和失败原因。

**FR-032 Notebook（C）**

- 用户可在项目内创建 Notebook，选择 IDE 类型、镜像、工作目录、环境变量、挂载、节点选择器、CPU、内存和 GPU。
- 支持 Jupyter、Theia 等 IDE 类型，具体类型取决于配置的镜像映射。
- 支持启动、停止、重置、续期、批量删除和进入在线 IDE。
- Notebook 状态应从 Kubernetes Pod 查询并显示；支持查看 Pod 详情、日志和调试终端。
- Notebook 默认挂载用户持久化目录，长期运行任务应转为 Pipeline；该提示属于当前实现约束。

### 5.5 任务模板、Pipeline 与工作流

**FR-040 任务模板（C）**

- 任务模板应定义镜像、版本、工作目录、入口点、参数、环境变量、强制挂载、特权模式、Kubernetes 账户和项目归属。
- 支持 Release/Alpha 版本和模板复制。
- 模板应可被任务、Notebook、训练或服务创建流程选择。

**FR-041 Pipeline 编排（C）**

- 用户可创建项目级 Pipeline，保存 DAG、全局环境变量、命名空间、节点选择器、镜像拉取策略和扩展布局。
- Pipeline 支持一次执行和 Cron 定时执行；可配置补录起点、最大并发任务数、最大活动实例、过期保留数、任务优先级、历史依赖、报警状态和报警用户。
- 用户可通过可视化编辑器增删任务、配置上下游依赖、保存和复制 Pipeline。
- 系统应将 Pipeline 转换为 Kubernetes/Argo 工作流定义并提交运行。
- 支持运行、停止/删除任务运行、查看运行历史、工作流 DAG、Pod、日志和监控。
- 支持单任务调试、运行中任务监听端口、任务输出和结果查看；具体结果类型由任务模板和前端组件决定。

**FR-042 任务执行（C）**

- 任务应支持镜像、工作目录、启动命令、参数、覆盖入口点、挂载、节点选择器、CPU、内存、GPU、RDMA、超时、重试、输出和监控配置。
- 支持运行、调试、查看日志、清理运行实例、跳过任务和删除任务。
- 任务执行必须受到项目成员权限和资源配额约束。

**FR-043 工作流实例（C）**

- 记录集群、命名空间、名称、标签、规格、状态、用户和附加状态。
- 支持按 Pipeline、运行 ID 和标签追溯实例。
- 支持停止、批量清理和查看节点详情、MinIO/对象存储结果。

**FR-044 ETL 编排（C）**

- 支持创建 ETL Pipeline 与 ETL Task，维护 DAG、全局配置、调度引擎、任务模板和任务参数。
- 支持接入 Airflow、Azkaban、DolphinScheduler 等调度实现入口；实际启用的引擎由部署配置决定。
- 支持提交、运行、复制、查看和删除 ETL Pipeline。

**FR-045 超参数搜索（C）**

- 支持定义搜索任务类型、并行试验数、最大执行时长、最大试验数、失败上限、目标指标、算法、参数空间和试验模板。
- 支持运行、停止、查看试验任务日志、进入实验容器和复制配置。

### 5.6 模型管理与推理服务

**FR-050 训练模型登记（C）**

- 管理模型名称、版本、描述、本地/远程路径、下载地址、项目、Pipeline、运行 ID、运行时间、框架、指标、MD5 和 API 类型。
- 支持模型下载、删除和部署入口。

**FR-051 通用内部服务（C）**

- 支持以项目为边界部署通用容器服务，配置镜像、命令、参数、环境变量、挂载、节点、端口、副本、CPU、内存、GPU 和域名。
- 支持部署、清理、查看服务 Pod/日志和监控。

**FR-052 推理服务（C）**

- 支持配置服务类型、模型名称/版本/路径/框架、输入输出、推理配置、镜像、启动参数、环境变量、挂载、节点、端口和资源。
- 支持调试、测试、生产三类部署流程，以及清理、复制和升级。
- 支持最小/最大副本、HPA、定时伸缩、健康检查、指标、Sidecar、优先级、限流、金丝雀和流量复制等配置入口。
- 支持多版本部署、滚动切换、旧版本清理和失败状态提示。
- 服务应提供 IP/域名访问入口和在线测试入口；域名、网关和认证行为由集群配置决定。
- 支持 TensorFlow、PyTorch、Triton/ONNX 等模型服务类型的配置入口，实际镜像和协议由平台配置决定。

### 5.7 AIHub、对话与模型应用

**FR-060 AIHub 模型市场（C）**

- 模型条目应包含 UUID、状态、文档、名称、领域、场景、类型、中文标签、描述、来源、示例图片、镜像、数据集、Notebook、任务模板、Pipeline、预训练模型、推理和服务配置、版本、热度及价格。
- 支持按视觉、语音、语言、多模态、AIGC 和全部分类浏览。
- 条目可提供模型文档、示例、开发环境、微调链路或部署配置；具体“一键”动作依赖配置数据。

**FR-061 对话应用（C）**

- 管理对话场景名称、图标、标签、文档、会话数量、对话类型、欢迎语、提示语、知识、Prompt 模板、服务类型、服务配置和可访问用户。
- 支持文本、语音、文本+语音、多模态、数字人等类型配置入口。
- 支持会话接口、清除会话缓存、上传/读取知识库配置、生成 Prompt、流式或非流式响应。
- 支持 ChatGPT 兼容接口和图像生成接口；外部服务 URL、Header 和请求结构由场景配置提供。
- 记录会话日志，包括问题、回答、人工反馈、状态、耗时和错误信息。

### 5.8 资源、日志与监控

**FR-070 Kubernetes 资源操作（C）**

- 支持按集群、命名空间和 Pod 查看 Pod 信息、状态、容器列表和资源详情。
- 支持查看/下载/读取 Pod 日志、按容器和尾行数读取、进入命令行调试、搜索 Pod/服务和强制删除异常 Pod。
- 所有破坏性操作必须进行权限校验和结果提示。

**FR-071 总体资源监控（C）**

- 提供节点、Pod、项目/命名空间维度的资源列表和图表接口。
- 资源至少包括 CPU、内存、GPU 等申请量/使用量；网络、磁盘、NPU、RDMA 等是否可用取决于监控适配器。
- 支持筛选、分页、图表选项、监控数据查询和管理员批量删除历史记录。

**FR-072 审计与用户提示（C）**

- 记录 API 访问日志和操作耗时。
- API 可通过 `api_flashes` 响应头返回成功、警告、错误提示，前端统一展示通知。
- 认证超时、网络不可用、资源不存在和任务失败应返回可读错误信息。

## 6. 核心业务流程

### 6.1 项目研发流程

1. 用户登录并进入项目空间。
2. 创建项目或加入已有项目，绑定集群、命名空间和资源配额。
3. 选择已有镜像/任务模板，或构建项目镜像。
4. 启动 Notebook 进行交互开发；代码和数据通过持久化挂载访问。
5. 将可重复逻辑配置为任务并组成 Pipeline。
6. 调试 Pipeline，提交一次性或定时运行。
7. 查看工作流实例、Pod 日志、输出结果和监控。

### 6.2 模型交付流程

1. 从 Pipeline 或外部路径登记训练模型。
2. 填写版本、框架、指标和模型路径。
3. 选择服务类型、镜像、资源和健康检查配置。
4. 先部署调试/测试环境，在线测试接口。
5. 发布生产版本，执行滚动升级或流量切换。
6. 查看服务负载、日志和版本状态；必要时清理或回滚旧版本。

### 6.3 对话应用流程

1. 管理员或项目用户创建对话场景。
2. 配置外部/内部大模型服务、Prompt、知识和访问范围。
3. 前端调用对话 API，支持历史会话和流式响应。
4. 系统记录会话日志、耗时、错误和人工反馈。

## 9. 非功能需求

### 9.1 安全

- 所有业务 API 默认需要认证和 RBAC。
- 必须启用 HTTPS、CSRF 防护、必要的 CORS 白名单和安全响应头。
- 密码、JWT 密钥、仓库凭证、外部服务秘钥不能明文出现在日志、前端响应和异常堆栈。
- 对 SQL、Shell、YAML、JSON、日志和 Markdown 等可执行/可渲染内容进行输入校验和输出转义。
- 记录管理员和高风险操作审计，保留期限由合规要求确定。

### 9.2 可用性与可靠性

- Kubernetes API、数据库、缓存、Celery 和外部服务故障时，界面应返回明确的降级状态和错误原因。
- 任务、服务和 Notebook 状态查询应支持超时、重试和最终一致性，避免重复提交。
- Pipeline 定时运行、服务升级和资源清理需要幂等；重复请求不能产生不可控的重复实例。
- 应提供备份恢复、数据库迁移、配置回滚和外部资源孤儿清理方案。**T**

### 9.3 性能

- 列表接口必须分页，筛选和排序在数据库侧执行。
- 大型日志、查询结果和工作流文件应流式读取或异步生成下载文件。
- Kubernetes 资源查询应支持缓存或批量查询，避免每个列表行单独调用集群 API。
- 目标并发、响应时间、任务提交吞吐和监控采样周期需由部署规模确认。**T**

### 9.4 可维护性与国际化

- 后端使用 Flask-Babel 文案，前端支持中英文资源和动态配置；正式支持语言数量需以交付版本确定。
- 扩展字段、配置项、镜像类型、服务类型和菜单定义应版本化。
- 数据库迁移必须通过 Alembic 执行，禁止直接修改生产表结构。

## 10. 验收标准（建议基线）

1. 未登录访问任一受保护 API 返回 401；登录后可根据角色显示不同菜单。
2. 项目创建者可以创建项目、添加成员、配置角色和配额；无权用户无法编辑或删除。
3. 开发者可以在项目内创建 Notebook，启动后能进入 IDE、查看状态、日志和 Pod 详情。
4. 开发者可以创建任务模板、Pipeline，完成保存、调试、运行、停止、日志查看和运行历史追踪。
5. 任务资源配置至少能表达 CPU、内存、GPU、RDMA、超时和重试，且最终下发到 Kubernetes 工作负载。
6. 用户可以登记模型并部署推理服务，能够完成测试环境验证、生产发布、监控和清理。
7. 用户可以创建对话场景并通过 API 获得响应，会话日志包含问题、回答、耗时和错误状态。
8. 管理员可以查看节点、Pod、服务资源信息和审计日志，并能执行受控的清理动作。
9. 关键失败场景（认证失败、资源不足、镜像拉取失败、Pod 启动失败、服务部署超时、外部模型错误）能返回可读提示并保留日志。
10. 数据库迁移、备份恢复、敏感数据保护和 API 权限矩阵通过专项安全与运维验收。

## 12. 已知实现风险

- 当前配置和扩展 JSON 较多，字段缺少统一 Schema，容易出现前后端约定漂移。
- 部分高风险动作直接通过 GET/自定义 URL 暴露，需确认 CSRF、幂等和审计策略。
- Kubernetes、数据库、Celery、监控和外部模型调用均依赖外部服务，代码中存在较多部署环境分支。
- README 的能力范围大于当前可从代码直接确认的闭环，不能据此承诺所有商业/增强功能。
- 资源、费用、租赁、计量、消息推送和多租户等能力存在配置/字段线索，但尚未形成完整的可验收需求。
