# ModelOne 工业作业台 UI 规范

> 版本：3.0（浅色左侧主导航）
> 适用范围：ModelOne 企业级 AI 生产平台 Web 控制台
> 关联规范：[ModelOne 品牌定义与 UI 视觉规范](./modelone-brand-and-ui-guidelines.md)

本文件是 ModelOne 视觉规范在控制台中的落地版本，重点约束壳层、左侧菜单、列表页密度和状态表达。它不替代权限、接口契约或现有路由。

CubeStudio 仍作为仓库、镜像、API、数据库和历史版本的兼容标识；新界面、标题、导航和对外文案统一使用 **ModelOne｜企业级 AI 生产平台**。

**3.0 相对 2.0 的硬性变更：** 取消石墨色顶栏作为一级导航。控制台必须使用浅色左侧主导航；深色只允许出现在日志、终端、代码检视窗，以及「智能助手」这一颗特色菜单项。

## 1. 设计定位

### 1.1 一句话

**面向算力与模型全生命周期的浅色作业台：让资源、流程、状态和风险在同一套可追溯系统中清晰可见。**

### 1.2 视觉母题

ModelOne 控制台使用 **Light Rail / 浅色导轨作业台**：浅灰导轨承载一级任务，白色工作面承载高密度业务，墨黑只用于当前动作和智能助手入口。

视觉关键词：**明亮、精确、克制、可扫描、少装饰。**

工业感来自结构和行为，不来自深色外壳或仿旧效果：

- **浅色导轨**：左侧 208px 一级菜单，浅灰底、线框图标、胶囊选中态。
- **白色工作面**：主区白底、1px 冷灰边界、高密度表格。
- **模块内栏**：当前一级模块的二级 / 三级树，浅底、圆角选中，不与主导航抢层级。
- **墨黑主操作**：新增、查询、发布等主动作用墨黑填充；不要把整条顶栏或整列导航涂黑。
- **检视窗**：代码、日志、YAML、JSON 仍使用深石墨表面，与业务数据形成层级差。

### 1.3 明确排除

- 不使用深色顶栏、深色侧栏、深色监控大屏作为默认壳层。
- 不使用蓝紫渐变、玻璃拟态、发光边缘、纹理背景、3D 设备插画或拟真金属贴图。
- 不把每个业务域染成一种颜色；模块用结构区分，颜色只承担状态和动作。
- 业务卡片、表格、输入框不使用大圆角、漂浮阴影或 Hover 上浮。胶囊圆角只允许用于左侧一级菜单项。
- 不用纯色状态点替代文字，不用假数据填满空状态。

## 2. 产品壳层与信息架构

### 2.1 应用框架

当前前端基于 React 17 + Ant Design 4。3.0 把一级导航从顶栏横排改为左侧竖排，菜单数据仍来自 `/myapp/menu`，不改变已有路由与业务语义。

```text
┌ 左侧主导航 208px（折叠 64px）· 浅灰导轨 ─────────────────────────────┐
│ Logo ModelOne + 折叠按钮                                            │
│ 智能助手          ← 特色项，墨黑胶囊                                 │
│ 项目空间 / 数据资产 / 在线开发 / 模型训练 / 服务化                     │
│ 更多 ▾            ← 溢出分组                                         │
│   AIHub / 算力租赁 / 安全设置 / 文档                                  │
│ 底部：当前空间·项目 + 用户                                           │
└──────────────────────────────────────────────────────────────────────┘
                    │
                    ▼
┌ 内容区 · 白底 ───────────────────────────────────────────────────────┐
│ 页面标题 + 一句说明 + 页内 Tabs（可选）                                │
│ ┌ 模块内栏 200px ┐  面包屑                                            │
│ │ 二级 / 三级树   │  工具栏：主操作 + 次操作 + 筛选 + 查询 / 重置        │
│ └────────────────┘  主表格 / 工作面 + 详情抽屉 / 日志检视窗            │
└──────────────────────────────────────────────────────────────────────┘
```

规则：

- 一级导航只出现在左侧，不再出现在顶栏。
- 内容区顶部是页面标题区，不是品牌顶栏。不要再做 56px 石墨色控制柜。
- 若模块只有一层叶子页，可隐藏模块内栏，主表格占满内容区。
- 文档、通知、帮助、用户入口放在左侧底部或标题区右上，不得重新变成一条深色顶栏。

### 2.2 左侧一级菜单

菜单来源仍是 `myapp/views/home.py` 的 `/myapp/menu`。展示层按「常驻项 + 更多 + 底部上下文」组织，不按截图里的 X-DATA 业务名复制。

| 顺序 | 菜单 | 来源 | 展示 |
| --- | --- | --- | --- |
| 1 | 智能助手 | `navbar_bottom` / `AiChatBot` | 常驻特色项，置于最顶 |
| 2 | 项目空间 | `projetc` | 常驻 |
| 3 | 数据资产 | `data` | 常驻 |
| 4 | 在线开发 | `dev` | 常驻 |
| 5 | 模型训练 | `ml` | 常驻 |
| 6 | 服务化 | `service` | 常驻 |
| 7 | 更多 | 溢出容器 | 默认收起 |
| 7.1 | AIHub | `aihub`（现 `hidden`，有权限则显示） | 放入更多 |
| 7.2 | 数据智能 | `chat`（现 `hidden`，有权限则显示） | 放入更多 |
| 7.3 | 算力租赁 / 费用 / 资源配置 | `aihub` 下管理员子树，或独立一级 | 放入更多 |
| 7.4 | 安全设置 | `security_setting`，仅管理员 | 放入更多 |
| 7.5 | 链接 | `links`，仅管理员 | 放入更多 |
| 7.6 | 文档 | `DOCUMENTATION_URL` | 放入更多或标题区右上 |
| 底 | 当前空间 / 项目 | `ProjectSwitcher` | 侧栏底部，浅色下拉 |
| 底 | 用户 / 退出 | 原顶栏用户菜单 | 侧栏底部 |

可见性仍由权限、`hidden`、`disable` 和会话上下文裁剪；无权限项不占位。空间 / 项目上下文规则见 [多空间多团队模型设计方案](./modelone/space-project-design.md)。

### 2.3 一级菜单视觉状态

| 状态 | 外观 |
| --- | --- |
| 默认 | 透明底，线框图标 16px，文字 14px / 500，`--mo-text-secondary` |
| Hover | 文字与图标变为 `--mo-ink`，无位移、无阴影 |
| 当前模块 | 白底胶囊 + 轻阴影 `--mo-shadow-nav`，文字 `--mo-ink` |
| 智能助手（特色） | 墨黑胶囊、白字白图标；未选中时仍保持墨黑，不与模块选中态抢白胶囊 |
| 禁用 | 保留条目，降低到 `--mo-text-tertiary`，Tooltip 说明原因 |
| 折叠 64px | 只保留图标；当前项仍是白胶囊，智能助手仍是墨黑圆钮；必须有 Tooltip 和 `aria-label` |

不要使用左侧 3px 色条、整块灰底矩形、彩色渐变或深色侧栏来表达选中。

### 2.4 模块内栏（二级 / 三级）

一级菜单只负责任务域。二级、三级来自该模块 `children`，渲染在内容区左侧的模块内栏：

```text
数据资产
├── 数据探索
│   └── sqllab
├── 元数据
│   ├── 库表
│   ├── 指标
│   └── 维表
└── 媒体数据
    ├── 数据集
    └── 标注平台
```

- 宽度 200px，白底，右侧 1px `--mo-border`。
- 分组可折叠；当前叶子项使用 `--mo-surface-muted` 圆角 8px 浅底，不要再用 3px 导轨。
- 叶子项带原 SVG 线框图标；图标颜色跟随文字，不使用彩色填充图标。
- `related` 且 `hidden: 1` 的项不进内栏，只在对象详情中出现。

### 2.5 信息优先级

任何页面 3 秒内应能回答：

1. 当前正在看哪个对象（项目、集群、任务、服务、数据集或模型版本）。
2. 对象处于什么状态，是否有阻塞（资源不足、失败、权限、配额或版本冲突）。
3. 当前区域唯一主动作是什么，执行后会改变什么状态。
4. 谁在什么时候做了什么，失败后如何恢复。

## 3. ModelOne 视觉令牌

### 3.1 颜色模型

采用 **浅灰导轨 + 白色工作面 + 墨黑主操作**。品牌动作统一使用墨黑；警告、成功和失败使用独立语义色。壳层背景必须是浅色。

| Token | 色值 | 角色 |
| --- | --- | --- |
| `--mo-bg` | `#F5F6F7` | 页面背景、左侧导轨 |
| `--mo-surface` | `#FFFFFF` | 表格、表单、工作面、选中胶囊 |
| `--mo-surface-muted` | `#F0F2F4` | 表头、模块内栏选中、禁用背景 |
| `--mo-surface-hover` | `#F8F9FA` | 悬停背景、行 Hover |
| `--mo-surface-selected` | `#E9EAEC` | 表格当前行 |
| `--mo-ink` | `#17191D` | 主文字、主按钮、智能助手胶囊 |
| `--mo-ink-hover` | `#262A31` | 主按钮悬停 |
| `--mo-text-secondary` | `#50545C` | 辅助信息、未选菜单、表头 |
| `--mo-text-tertiary` | `#737985` | 占位、时间、说明、面包屑 |
| `--mo-border` | `#E5E6EB` | 结构线、表格行、内栏分隔 |
| `--mo-border-strong` | `#C9CDD4` | 输入框、次按钮 |
| `--mo-brand-primary` | `#17191D` | 主操作填充、查询按钮 |
| `--mo-brand-primary-hover` | `#262A31` | 主操作悬停 |
| `--mo-brand-primary-active` | `#0E1013` | 主操作按下 |
| `--mo-brand-primary-soft` | `#E9EAEC` | 浅色提示 |
| `--mo-brand-text` | `#17191D` | 浅色背景上的强调文字 |
| `--mo-brand-contrast` | `#FFFFFF` | 墨黑按钮 / 智能助手上的文字 |

墨黑与白色的对比度约为 17.4:1。主操作和智能助手使用墨黑背景 + 白色文字；其余导航必须浅色。

### 3.2 状态与风险色

状态必须同时使用颜色、文字和图标 / 实心点。状态色不用于装饰，不用于模块身份，也不用于导航选中。

| 状态角色 | Token | 色值 | 示例 |
| --- | --- | --- | --- |
| Success | `--mo-success` | `#16825D` | 成功、已完成、已发布、健康 |
| Running | `--mo-info` | `#1769AA` | 运行中、构建中、处理中、就绪 |
| Warning | `--mo-warning` | `#A65F00` | 排队、部分完成、配额临界、待处理 |
| Danger | `--mo-danger` | `#C7353C` | 失败、异常、停止、删除风险 |
| Neutral | `--mo-text-tertiary` | `#737985` | 草稿、未启动、归档、无数据 |
| Restricted | `--mo-text-secondary` | `#50545C` | 无权限、私有、锁定、只读 |

规则：

- 成功、运行中、警告和失败均配固定文字；不得只显示色点。
- 资源利用率 0–70% 为中性或运行中，70–85% 为警告，超过 85% 为危险；具体阈值以项目策略为准。
- 训练、服务、Notebook 等业务状态可保留后端原值，但展示层必须映射到本表语义。
- 图表默认使用信息蓝；对照目标使用墨黑；阈值线使用警告色并带文字标签。

### 3.3 字体与数字

为适配内网离线部署，不默认依赖远程字体：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
font-variant-numeric: tabular-nums;
```

代码、资源 ID、版本号和指标值使用：

```css
font-family: "IBM Plex Mono", "SFMono-Regular", Consolas, monospace;
```

只使用 400（正文）、500（标签与导航）、600（标题与主操作）三个字重。

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | 20px / 600 / 28px | 内容区标题，如「数据资产」 |
| 页面说明 | 13px / 400 / 20px | 标题右侧一句能力说明 |
| 区块标题 | 16px / 600 / 24px | 面板、抽屉、分组 |
| 组件标题 | 14px / 600 / 22px | 卡片、表格、详情 |
| 正文 | 14px / 400 / 22px | 表单、说明、表格 |
| 导航 | 14px / 500 / 22px | 左侧一级菜单 |
| 辅助 | 13px / 400 / 20px | 时间、帮助、标签、筛选 |
| 设备标识 | 12px / 400 / 18px 等宽 | Pod、任务、版本、镜像、端口 |
| 日志 / 代码 | 12–13px / 400 / 20px 等宽 | 命令、YAML、堆栈、JSON |

正文和 UI 标签的字间距保持 `0`。数字、ID、镜像标签、时间和版本号使用等宽字体；数值右对齐，单位与数值同时出现，例如 `8 / 16 GiB`、`72.4%`、`12.4 s`。缺省值统一使用 `—`。

### 3.4 尺度、线条、圆角和阴影

- 4px 基础网格，优先使用 `4 / 8 / 12 / 16 / 24 / 32 / 48px`。
- 左侧主导航 208px，折叠 64px；模块内栏 200px；默认控件 32px，表格行 40px，密集作业台行 32px。
- 一级菜单项高度 40px，左右内边距 12px，项间距 4px。
- 结构线 1px `--mo-border`；输入与次按钮 1px `--mo-border-strong`。
- 圆角：表格 / 小工具 2px；按钮、输入、标签 4px；模块内栏选中 8px；一级菜单胶囊 `999px`；抽屉、弹窗 6px。
- 默认无阴影。一级菜单当前项使用 `--mo-shadow-nav: 0 1px 4px rgba(23, 25, 29, .08)`。浮层使用 `0 8px 24px rgba(23, 25, 29, .16)`。Hover 不改变尺寸、不上浮。
- 深色检视窗使用深色表面 + 1px 边界，不给普通卡片或导航套深色外壳。

## 4. 组件规范（Ant Design 4 映射）

### 4.1 左侧主导航

- 背景 `--mo-bg`，不要用 `--mo-ink`。
- 顶部：浅色背景横版 Logo `modelone-logo.svg`，高度 28px；右侧折叠按钮。折叠后改用 `modelone-mark.svg`。
- 菜单项是胶囊，不是 Ant Design 默认的带右边框竖条。需要覆盖 `.ant-menu-inline .ant-menu-item::after { border: 0 }`。
- 「更多」是分组，不是新的一级业务模块；展开后项样式与常驻项相同。
- 底部项目切换器使用浅色 Select：白底、`--mo-border-strong` 边框、墨黑文字。不要沿用深色顶栏里的反白选择器。
- 折叠后保留图标、Tooltip 和 `aria-label`；图标不能单独承载不可猜的业务含义。

### 4.2 内容标题区与 Tabs

列表页标题区结构对齐参考截图：

```text
数据资产     登记数据集位置、版本和校验状态，供训练与推理读取
数据探索   元数据   媒体数据          ← 页内 Tabs，当前项墨黑字 + 底部 2px 墨黑线
```

- 标题 20px / 600，说明 13px / `--mo-text-tertiary`，同一行。
- Tabs 在标题下方，浅底、无卡片边框；未选中 `--mo-text-secondary`。
- 有模块内栏时，标题区仍横跨内容区顶部，内栏从标题区下方开始。
- 面包屑放在工具栏上一行，例如 `数据资产 / 数据集`。

### 4.3 按钮

- `Primary`：每个区域最多一个，动词开头，如「新增」「查询」「创建任务流」。背景 `--mo-brand-primary`，文字 `--mo-brand-contrast`，高度 32px，圆角 4px。
- `Default`：白底 + `--mo-border-strong`，适合删除、发布至网关、重置、返回。
- `Link`：表格行内动作，如「编辑 / 发布 / 下线」；颜色 `--mo-text-secondary`，Hover 变为 `--mo-ink`。不要把所有行内动作做成品牌色链接。
- `Danger`：停止、删除、释放和回滚等动作使用危险语义；必须说明对象、影响范围和是否可恢复。
- `disabled`：保留按钮并解释原因，例如「资源组配额不足，无法启动」。
- 图标按钮必须有 Tooltip 和 `aria-label`。

工具栏顺序固定为：主操作 → 次操作 → 弹性空白 → 筛选控件 → 查询（Primary）→ 重置（Default）。

### 4.4 表格

- 表头 36px，背景 `--mo-surface-muted`，文字 13px / 500 / `--mo-text-secondary`。
- 常规行 40px，任务 / 日志台 32px；行间 1px `--mo-border`，不用卡片阴影。
- 第一列可勾选；第二列固定核心标识：任务名、服务名、数据集、Pod 或模型版本；操作列固定右侧，使用 Link 按钮。
- 状态列使用 `图标 + 文字`；资源数值、延迟、版本、时间右对齐并使用等宽字体。
- 行内保留 1–3 个高频动作，其余收进「更多」；危险动作不与普通动作无间隔相邻。
- 当前行或 Hover 使用 `--mo-surface-hover`，不要加左边彩条。
- 长名称省略但可通过 Tooltip / Drawer 查看全文；超长 ID 不换行。
- 大数据集、Pod、日志列表使用服务端分页、筛选和排序。

### 4.5 筛选、表单和动态表单

- Label 始终可见，Placeholder 不代替 Label；必填用文字 / 标记说明。
- 关键上下文筛选外露：项目组、集群、资源组、状态、时间；低频条件放入「更多筛选」。
- 筛选控件高度 32px，与查询 / 重置对齐。
- 资源选择器按「集群 → 资源组 → 资源规格」分层；展示可用量、已用量和配额，不只展示名称。
- 校验在失焦后出现，错误贴近字段；提交失败保留已填值并给出恢复动作。
- 动态表单分组标题使用业务对象，不用连续卡片包裹；高级参数可折叠但不能丢失已填内容。

### 4.6 状态标签、进度和通知

- 状态标签固定为 `● 文字` 或 `图标 + 文字`，背景使用状态色 8–12% 透明度。
- 进度必须同时显示完成 / 总数、状态、最近更新时间和失败条数；不使用跳动光点代替文字。
- 任务状态变化写回对象页；Toast 只做即时反馈，不能承载需要后续处理的失败、配额和权限问题。
- 长时间任务使用页面内 Error / Warning 条，提供「重试、查看日志、调整资源、停止」等动作。

### 4.7 Modal、Drawer 和检视窗

- 短确认用 Modal；资源详情、任务上下文、服务配置、审计事件用 Drawer；宽度 480–640px。
- 日志、YAML、JSON、终端使用深色检视窗，顶部显示对象 ID、集群 / 命名空间和复制 / 下载动作。这是控制台里唯一允许的成片深色。
- 危险确认必须写清对象名称、影响范围、是否可恢复；关闭后焦点回到触发点。
- 抽屉内不要再套浮动卡片；用标题、分组线和 12–16px 内边距组织内容。

### 4.8 卡片与首页

首页是工作台，不是营销页。功能入口优先使用带图标的紧凑模块项或表格，不使用大量 180px 图片卡片。统计卡仅用于 4–6 个可行动指标，每项必须有更新时间、范围和跳转入口。卡片白底、1px 边，不要深色卡片。

智能助手从右下角悬浮球升级为左侧第一项。点击后进入对话工作面；原 `AiChatBot` 悬浮入口可保留为折叠态的快捷入口，但不再是唯一入口。

## 5. 关键页面模板

### 5.1 列表页（默认模板）

绝大多数资源页（数据集、镜像、任务流、推理服务、项目分组）使用同一模板：

```text
标题：推理服务          说明：把已注册模型发布为可观测的在线服务
Tabs（若该一级下有并列子域）
┌ 模块内栏 ┐  面包屑：服务化 / 推理服务
│ 模型管理  │  [新增] [删除]     状态▾  集群▾  名称____  [查询] [重置]
│ 推理服务● │  表格：名称 / 模型版本 / 环境 / 副本 / 状态 / 更新时间 / 操作
│ 服务网关  │  操作列：编辑  发布  下线
└───────────┘
```

### 5.2 工作台 / 资源总览

第一视线显示：当前项目、可用算力、运行中任务、异常告警和最近模型发布。把「创建任务流」作为主操作，把教程和视频放到帮助或空状态中。

```text
页面标题：平台总览       上下文：项目组 / 集群 / 时间范围       主动作：创建任务流
┌ 运行队列 ┐ ┌ GPU 利用率 ┐ ┌ 在线服务 ┐ ┌ 失败任务 ┐
├───────────┴────────────┴────────────┴───────────┤
│ 资源分配：集群 / 资源组 / CPU / GPU / 内存 / 存储             │
├──────────────────────────┬──────────────────────┤
│ 最近任务与失败原因        │ 服务健康与请求趋势     │
└──────────────────────────┴──────────────────────┘
```

### 5.3 数据资产 / 数据探索

- 主区使用数据集 / 元数据表格，固定数据集名称、版本、状态和责任人。
- 详情 Drawer 展示来源、容器路径、存储大小、条目数、校验状态和最近使用任务。
- SQLLab / 数据探索保持编辑器 + 结果表结构；运行中显示查询 ID、耗时、取消动作和错误定位。
- 空状态必须说明是「尚未接入数据」还是「当前项目无权限」，分别给出接入或申请权限入口。

### 5.4 在线开发 / Notebook / 镜像

- 镜像管理采用「仓库 / 标签 / 架构 / 构建状态 / 最近使用」表格；Dockerfile 和构建日志进入深色检视窗。
- Notebook 启动页先显示项目组、集群、资源组、规格、存储挂载和预计配额消耗，再显示启动按钮。
- 启动按钮旁始终展示资源可用量；不可启动时解释是配额、节点、镜像还是权限原因。
- 终端和代码区域允许横向滚动，保持等宽字体和复制入口，不用彩色背景装饰。

### 5.5 Pipeline / 任务流 / 训练

- 左侧为模板 / 节点目录，中间为流程画布，右侧为节点配置 Drawer；画布节点使用中性表面 + 状态边缘。
- 节点颜色只表达状态：未配置 Neutral、排队 Warning、运行 Running、成功 Success、失败 Danger。
- 运行详情顶部显示任务流 ID、集群、命名空间、创建者、开始时间、耗时、当前阶段和失败节点。
- 资源配置与运行日志并列展示；停止、重试、重新运行必须写明是否复用输出和是否产生新运行 ID。
- 画布连线使用 `#8A979D`，失败分支使用危险色；禁止节点类别彩虹化。

### 5.6 模型与服务

- 服务列表固定显示服务名、模型版本、环境、副本、健康状态、QPS / 延迟和最近发布人。
- 发布流程采用「模型版本 → 资源规格 → 环境 → 健康检查 → 流量策略 → 确认」的步骤；每步显示前置校验。
- 运行中和健康检查使用 Running / Success；发布失败保留日志链接、失败阶段和重试动作。
- 回滚是 Danger 语义，但必须提供目标版本和影响流量范围；灰度 / A-B 使用图表对照，不用彩色大卡。

### 5.7 资源、集群与监控

- 集群页先给拓扑摘要：集群状态、节点数、GPU / CPU / 内存 / 存储利用率、异常节点数。
- 节点与 Pod 列表固定集群、命名空间、资源组、节点 IP / Pod 名称、申请量、使用量和状态。
- 监控图表默认一条信息蓝序列；比较目标用墨黑；阈值线带数值标签。
- 高利用率用 Warning / Danger 文案和动作入口（调整资源、迁移、暂停、联系管理员），不要只把曲线染红。

### 5.8 模型市场 / 智能体

- 模型市场优先使用可筛选目录表格：模型名、任务类型、框架、版本、资源要求、维护状态、最近更新时间。
- 模型详情页以 README、版本、运行要求、示例和部署入口为主；封面图只作辅助，不做大幅视觉主角。
- 资源租赁显示库存、规格、租期、费用和释放规则；费用与运行状态分开表达。

## 6. 状态与可访问性

### 6.1 统一展示词

| 领域 | 状态词 |
| --- | --- |
| 通用任务 | 未启动、排队中、运行中、成功、失败、已停止、已取消、部分完成 |
| Pipeline / 训练 | 草稿、待运行、运行中、暂停、成功、失败、已停止、已归档 |
| Notebook | 创建中、运行中、空闲、已停止、异常、已过期 |
| 镜像构建 | 待构建、构建中、构建成功、构建失败、已下线 |
| 服务 | 未部署、部署中、健康、降级、异常、已停止、已回滚 |
| 数据集 | 草稿、可用、校验中、校验失败、已归档、无权限 |
| 资源 | 可用、使用中、配额临界、已耗尽、离线、维护中 |

展示层不要把同一语义写成多个词，例如不要同时使用「执行中 / 正在执行 / 运行中」；统一为「运行中」。后端原始值可以在详情中作为 source status 展示，但不能作为主标签直接暴露给普通用户。

### 6.2 状态覆盖

所有列表、表格、编辑器、运行详情和发布动作必须覆盖：

| 状态 | 设计要求 |
| --- | --- |
| Loading | 300ms 后显示局部 Skeleton；15s 后提示仍在加载并提供重试 |
| Empty | 说明原因 + 下一步，例如「暂无可用资源 → 配置资源组」 |
| Error | 问题、原因、恢复动作；保留筛选和已填内容 |
| Populated | 主路径，默认显示更新时间和范围 |
| Disabled | 控件保留，旁边解释不可用原因 |
| Hover / Focus / Selected | 键盘可达，焦点环不只依赖颜色 |
| Success | 写回对象状态，同时保留日志 / 版本 / 时间 |
| Edge | 超长名称、缺字段、零资源、海量失败行不破版 |
| Permission | 入口按权限隐藏或显示 403；不要让用户点击后才发现无权限 |

### 6.3 可访问性底线

- 正文 / 控件对比度至少 WCAG 2.2 AA；触控目标不小于 32px。
- 图标按钮有 `aria-label`；状态有文字，不只靠颜色。
- 创建任务、启动 Notebook、停止运行、发布服务、查看日志等核心路径可键盘完成。
- 动态进度使用文字状态，必要时 `aria-live="polite"`；避免持续闪烁和无意义动画。
- Modal / Drawer 关闭后焦点回到触发控件；折叠侧栏对图标提供 Tooltip。

## 7. 响应式规则

| 宽度 | 行为 |
| --- | --- |
| ≥ 1440px | 208px 主导航 + 200px 模块内栏 + 主工作区 |
| 1100–1439px | 主导航保留；模块内栏可收起，详情退化为主区 + Drawer |
| 768–1099px | 主导航折叠为 64px；模块内栏默认收起 |
| < 768px | 主导航改为抽屉；表格转为关键字段 + 抽屉详情；操作保留在底部工具栏 |

禁止固定 1920px 画布、绝对定位拼整页和依赖 Hover 才能完成的核心动作。表格、代码和日志在窄屏允许横向滚动；标题、ID 和按钮不能相互遮挡。

## 9. 设计评审清单

- 一级导航是否在浅色左侧，而不是深色顶栏？
- 除智能助手外，是否没有任何整块深色导航或深色页头？
- 3 秒内能否看到当前项目 / 对象、状态和最严重阻塞？
- 每个区域是否只有一个明确主动作？危险动作是否解释后果？
- 当前模块是否使用白胶囊 + 轻阴影，而不是色条或灰矩形？
- 状态是否同时有文字、图标 / 色点和可恢复动作？
- ID、版本、时间和资源数值是否可扫描且使用等宽字体？
- 是否覆盖 Loading、Empty、Error、Disabled、Permission、Edge？
- 是否还存在渐变、毛玻璃、卡片上浮、彩虹节点或装饰性指标？
- 日志 / JSON / YAML 是否进入深色检视窗，普通业务表格是否保持浅色？
- 首页是否直接呈现资源、任务和服务状态，而不是教程卡片占据第一视觉？
- 窄屏下标题、按钮、表格和日志是否可读、可滚动、无重叠？

## 10. 兼容与发布要求

- 保留 API、数据库 app 标识、镜像仓库路径、已有 URL 和历史资源路径；品牌迁移与壳层改版不与代码仓库重命名绑定在同一发布中。
- `/myapp/menu` 的 JSON 字段保持兼容；前端负责「常驻 + 更多」的展示折叠，不要求后端重排。
- 在文档、示例 Pipeline 和 SDK 中增加「ModelOne（原 CubeStudio）」过渡说明，至少保留一个完整版本周期。
- UI 文案、页面标题、favicon、登录页、404 页和加载页使用 ModelOne；登录页背景保持浅色，Logo 使用 `modelone-logo.svg`，不要使用反白标去配深色顶栏。
- 每次迁移页面都要在 1440px、1024px、768px 和 390px 宽度验证布局，并检查长名称、海量表格和无权限状态。
