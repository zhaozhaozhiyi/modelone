# ModelOne 工业作业台 UI 规范

> 版本：2.0（ModelOne 品牌迁移版）
> 适用范围：ModelOne 企业级 AI 生产平台 Web 控制台
> 关联规范：[ModelOne 品牌定义与 UI 视觉规范](./modelone-brand-and-ui-guidelines.md)

本文件是 ModelOne 视觉规范在控制台中的落地版本，重点约束算力、数据、开发、训练、服务、模型市场和治理页面的布局、密度、状态和交互。它不替代权限、接口契约或现有路由。

CubeStudio 仍作为仓库、镜像、API、数据库和历史版本的兼容标识；新界面、标题、导航和对外文案统一使用 **ModelOne｜企业级 AI 生产平台**。

## 1. 设计定位

### 1.1 一句话

**面向算力与模型全生命周期的工业作业台：让资源、流程、状态和风险在同一套可追溯系统中清晰可见。**

### 1.2 视觉母题

ModelOne 使用 **Ink Production / 墨黑作业台** 作为视觉母题：墨黑承载稳定的基础设施，灰阶表达层级、边界和当前动作，浅色工作面承载高密度生产信息。

视觉关键词：**精确、坚实、明亮、可观测、少装饰。**

工业感来自结构和行为，不来自贴图或仿旧效果：

- **控制柜**：石墨色顶部框架、分区明确的导航、稳定的 56px 工具栏。
- **钢制工作面**：浅灰背景、白色业务面板、1px 冷灰边界，承载高密度表格。
- **检修标签**：等宽 ID、端口、集群、版本、状态点和操作日志。
- **墨黑主色**：品牌墨黑用于主操作、链接和当前导轨；警告使用独立语义色。
- **检视窗**：代码、日志、YAML、JSON 和图表使用深石墨表面，与业务数据形成层级差。

### 1.3 明确排除

- 不使用蓝紫渐变、玻璃拟态、发光边缘、纹理背景、3D 设备插画或拟真金属贴图。
- 不把整页做成深色监控大屏；深色只用于日志、终端、代码和局部检视窗。
- 不把每个业务域染成一种颜色；模块用结构区分，颜色只承担状态和动作。
- 不使用大圆角、漂浮卡片、Hover 上浮或连续闪烁表达“工业感”。
- 不用纯色状态点替代文字，不用假数据填满空状态。

## 2. 产品壳层与信息架构

### 2.1 应用框架

当前前端基于 React 17 + Ant Design 4，保留现有 56px 顶栏、横向一级模块导航和可折叠侧栏。迁移只改变材质、层级、密度和状态表达，不改变已有路由与业务语义。

```text
顶栏 56px · 石墨色控制柜框架
├── ModelOne 标识
├── 一级模块：工作台 / 算力 / 数据 / 开发与编排 / 训练与评测 / 模型与服务 / 模型与应用
├── 当前项目组 / 集群上下文
└── 通知 / 帮助 / 用户 / 退出

侧栏 232px（折叠 64px）· 浅色工作区
├── 当前模块的二级菜单
├── 分组标题和资源计数
└── 折叠控制

主工作区
├── 页面标题 + 面包屑 + 当前对象 / 状态
├── 关键指标带或运行进度（可选）
├── 筛选、搜索和工具栏
└── 主表格 / 工作面 + 详情抽屉 / 日志检视窗
```

### 2.2 一级模块排序

| 模块 | 业务对象 | 默认图标语义 |
| --- | --- | --- |
| 工作台 | 项目、任务、服务、异常 | `DashboardOutlined` |
| 算力 | 集群、节点、GPU/NPU、资源组、计量 | `ClusterOutlined` |
| 数据 | 数据集、元数据、数据探索、标注 | `DatabaseOutlined` |
| 开发与编排 | 镜像、Notebook、任务模板、Pipeline | `CodeOutlined` |
| 训练与评测 | 训练实例、超参搜索、模型评测、注册 | `DeploymentUnitOutlined` |
| 模型与服务 | 模型版本、推理服务、网关、流量 | `CloudServerOutlined` |
| 模型与应用 | AIHub、智能体、知识库、应用 | `AppstoreOutlined` |
| 监控与治理 | 资源监控、用户、权限、日志、审计 | `SafetyCertificateOutlined` |

图标只辅助定位，不能替代文字。当前模块使用浅灰底 + 左侧 3px 墨黑导轨；不使用整块彩色渐变选中态。

### 2.3 信息优先级

任何页面 3 秒内应能回答：

1. 当前正在看哪个对象（项目、集群、任务、服务、数据集或模型版本）。
2. 对象处于什么状态，是否有阻塞（资源不足、失败、权限、配额或版本冲突）。
3. 当前区域唯一主动作是什么，执行后会改变什么状态。
4. 谁在什么时候做了什么，失败后如何恢复。

## 3. ModelOne 视觉令牌

### 3.1 颜色模型

采用 **浅灰画布 + 白色工作面 + 石墨框架 + 墨黑主色**。品牌动作统一使用墨黑；警告、成功和失败使用独立语义色。

| Token | 色值 | 角色 |
| --- | --- | --- |
| `--mo-bg` | `#F5F6F7` | 页面背景 |
| `--mo-surface` | `#FFFFFF` | 表格、表单、工作面 |
| `--mo-surface-muted` | `#F0F2F4` | 表头、侧栏分组、禁用背景 |
| `--mo-surface-hover` | `#F8F9FA` | 悬停背景 |
| `--mo-surface-selected` | `#E9EAEC` | 当前行 / 当前对象浅灰底 |
| `--mo-ink` | `#17191D` | 顶栏、深色检视窗、主文字 |
| `--mo-ink-hover` | `#262A31` | 深色框架悬停 |
| `--mo-text-secondary` | `#50545C` | 辅助信息、表头 |
| `--mo-text-tertiary` | `#737985` | 占位、时间、说明 |
| `--mo-border` | `#D9DCE1` | 结构线、表格行 |
| `--mo-border-strong` | `#B8BDC6` | 输入框、按钮、分隔 |
| `--mo-brand-primary` | `#17191D` | 品牌主色、主操作填充 |
| `--mo-brand-primary-hover` | `#262A31` | 主操作悬停 |
| `--mo-brand-primary-active` | `#0E1013` | 主操作按下 |
| `--mo-brand-primary-soft` | `#E9EAEC` | 选中背景、浅色提示 |
| `--mo-brand-text` | `#17191D` | 浅色背景上的品牌强调文字 |
| `--mo-brand-contrast` | `#FFFFFF` | 墨黑主操作上的文字与图标 |

墨黑与白色的对比度约为 17.4:1；主操作使用墨黑背景 + 白色文字。

### 3.2 状态与风险色

状态必须同时使用颜色、文字和图标 / 实心点。状态色不用于装饰，不用于模块身份。

| 状态角色 | Token | 色值 | 示例 |
| --- | --- | --- | --- |
| Success | `--mo-success` | `#16825D` | 成功、已完成、已发布、健康 |
| Running | `--mo-info` | `#1769AA` | 运行中、构建中、处理中、就绪 |
| Warning | `--mo-warning` | `#A65F00` | 排队、部分完成、配额临界、待处理 |
| Danger | `--mo-danger` | `#C7353C` | 失败、异常、停止、删除风险 |
| Neutral | `--mo-text-tertiary` | `#737985` | 草稿、未启动、归档、无数据 |
| Restricted | `--mo-text-secondary` | `#50545C` | 无权限、私有、锁定、只读 |

规则：

- 成功、运行中、警告和失败均配固定文字；不得只显示色点。
- 资源利用率 0–70% 为中性或运行中，70–85% 为警告，超过 85% 为危险；具体阈值以项目策略为准。
- 训练、服务、Notebook 等业务状态可保留后端原值，但展示层必须映射到本表语义。
- 图表默认使用信息蓝；对照目标使用墨黑；阈值线使用警告色并带文字标签。

### 3.3 字体与数字

为适配内网离线部署，不默认依赖远程字体：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
font-variant-numeric: tabular-nums;
```

代码、资源 ID、版本号和指标值使用：

```css
font-family: "IBM Plex Mono", "SFMono-Regular", Consolas, monospace;
```

只使用 400（正文）、500（标签与导航）、600（标题与主操作）三个字重。

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | 24px / 600 / 32px | 模块页、对象页标题 |
| 区块标题 | 18px / 600 / 26px | 面板、抽屉、分组 |
| 组件标题 | 16px / 600 / 24px | 卡片、表格、详情 |
| 正文 | 14px / 400 / 22px | 表单、说明、表格 |
| 辅助 | 13px / 400 / 20px | 时间、帮助、标签 |
| 设备标识 | 12px / 400 / 18px 等宽 | Pod、任务、版本、镜像、端口 |
| 日志 / 代码 | 12–13px / 400 / 20px 等宽 | 命令、YAML、堆栈、JSON |

正文和 UI 标签的字间距保持 `0`；英文全大写标签使用 `0.06em` 至 `0.1em`；标题不使用大幅负字间距。数字、ID、镜像标签、时间和版本号使用等宽字体；数值右对齐，单位与数值同时出现，例如 `8 / 16 GiB`、`72.4%`、`12.4 s`。缺省值统一使用 `—`。

### 3.4 尺度、线条、圆角和阴影

- 4px 基础网格，优先使用 `4 / 8 / 12 / 16 / 24 / 32 / 48px`。
- 顶栏 56px，默认控件 36px，紧凑控件 32px，表格行 40px，密集作业台行 32px。
- 结构线 1px `--mo-border`；强边界 1px `--mo-border-strong`；当前导轨 / 风险边缘 3px。
- 表格和小工具圆角 2px；按钮、输入、标签 4px；抽屉、弹窗、下拉 6px；不使用 10px 以上的大圆角。
- 默认无阴影；浮层只用 `0 8px 24px rgba(23, 25, 29, .16)`。Hover 不改变尺寸、不上浮、不加光晕。
- 深色检视窗使用深色表面 + 1px 边界，不给普通卡片套深色外壳。

## 4. 组件规范（Ant Design 4 映射）

### 4.1 顶栏、侧栏和导航

- 顶栏背景 `--mo-ink`，高度 56px；ModelOne 标识使用石墨框架与彩色魔方，不使用渐变 Logo。
- 顶栏一级导航使用透明底；当前项用底部 3px 白色线，Hover 使用 `--mo-ink-hover`。
- 侧栏为 `--mo-surface`，右侧 1px 边界；二级菜单当前项使用 `--mo-surface-selected` + 左侧 3px 导轨。
- 折叠后保留图标、Tooltip 和 `aria-label`；图标不能单独承载不可猜的业务含义。
- 用户、项目组、集群上下文始终显示，避免在不同模块中丢失工作范围。

### 4.2 按钮

- `Primary`：每个区域最多一个，动词开头，如“创建任务流”“启动 Notebook”“发布模型服务”。背景 `--mo-brand-primary`，文字 `--mo-brand-contrast`。
- `Default`：边界 `--mo-border-strong`，白底，适合筛选、返回、查看日志。
- `Link / Ghost`：只用于低频或行内动作；不要把所有表格操作都做成品牌色链接。
- `Danger`：停止、删除、释放和回滚等动作使用危险语义；必须说明对象、影响范围和是否可恢复。
- `disabled`：保留按钮并解释原因，例如“资源组配额不足，无法启动”。
- 图标按钮必须有 Tooltip 和 `aria-label`；熟悉动作使用图标，陌生动作使用图标 + 文字。

### 4.3 表格

- 表头 36px，常规行 40px，任务 / 日志台 32px；行间用 1px 线，不用卡片阴影。
- 第一列固定核心标识：任务名、服务名、数据集、Pod 或模型版本；操作列固定右侧。
- 状态列使用 `图标 + 文字`；资源数值、延迟、版本、时间右对齐并使用等宽字体。
- 行内保留 1–2 个高频动作，其余收进“更多”；危险动作不与普通动作相邻无间隔排列。
- 长名称省略但可通过 Tooltip / Drawer 查看全文；超长 ID 不换行，允许横向查看或复制。
- 大数据集、Pod、日志列表使用服务端分页、筛选和排序，不一次性渲染全量数据。

### 4.4 筛选、表单和动态表单

- Label 始终可见，Placeholder 不代替 Label；必填用文字 / 标记说明。
- 关键上下文筛选外露：项目组、集群、资源组、状态、时间；低频条件放入“更多筛选”。
- 资源选择器按“集群 → 资源组 → 资源规格”分层；展示可用量、已用量和配额，不只展示名称。
- 校验在失焦后出现，错误贴近字段；提交失败保留已填值并给出恢复动作。
- 动态表单分组标题使用业务对象，不用连续卡片包裹；高级参数可折叠但不能丢失已填内容。

### 4.5 状态标签、进度和通知

- 状态标签固定为 `● 文字` 或 `图标 + 文字`，背景使用状态色 8–12% 透明度。
- 进度必须同时显示完成 / 总数、状态、最近更新时间和失败条数；不使用跳动光点代替文字。
- 任务状态变化写回对象页；Toast 只做即时反馈，不能承载需要后续处理的失败、配额和权限问题。
- 长时间任务使用页面内 Error / Warning 条，提供“重试、查看日志、调整资源、停止”等动作。

### 4.6 Modal、Drawer 和检视窗

- 短确认用 Modal；资源详情、任务上下文、服务配置、审计事件用 Drawer；宽度 480–640px。
- 日志、YAML、JSON、终端使用深色检视窗，顶部显示对象 ID、集群 / 命名空间和复制 / 下载动作。
- 危险确认必须写清对象名称、影响范围、是否可恢复；关闭后焦点回到触发点。
- 抽屉内不要再套浮动卡片；用标题、分组线和 12–16px 内边距组织内容。

### 4.7 卡片与首页

首页是工作台，不是营销页。功能入口优先使用带图标的紧凑模块项或表格，不使用大量 180px 图片卡片。统计卡仅用于 4–6 个可行动指标，每项必须有更新时间、范围和跳转入口。

## 5. 关键页面模板

### 5.1 工作台 / 资源总览

第一视线显示：当前项目、可用算力、运行中任务、异常告警和最近模型发布。把“创建任务流”作为主操作，把教程和视频放到帮助或空状态中。

```text
页面标题：平台总览       上下文：项目组 / 集群 / 时间范围       主动作：创建任务流
┌ 运行队列 ┐ ┌ GPU 利用率 ┐ ┌ 在线服务 ┐ ┌ 失败任务 ┐
├───────────┴────────────┴────────────┴───────────┤
│ 资源分配：集群 / 资源组 / CPU / GPU / 内存 / 存储             │
├──────────────────────────┬──────────────────────┤
│ 最近任务与失败原因        │ 服务健康与请求趋势     │
└──────────────────────────┴──────────────────────┘
```

### 5.2 数据资产 / 数据探索

- 主区使用数据集 / 元数据表格，固定数据集名称、版本、状态和责任人。
- 详情 Drawer 展示来源、容器路径、存储大小、条目数、校验状态和最近使用任务。
- SQLLab / 数据探索保持编辑器 + 结果表结构；运行中显示查询 ID、耗时、取消动作和错误定位。
- 空状态必须说明是“尚未接入数据”还是“当前项目无权限”，分别给出接入或申请权限入口。

### 5.3 在线开发 / Notebook / 镜像

- 镜像管理采用“仓库 / 标签 / 架构 / 构建状态 / 最近使用”表格；Dockerfile 和构建日志进入深色检视窗。
- Notebook 启动页先显示项目组、集群、资源组、规格、存储挂载和预计配额消耗，再显示启动按钮。
- 启动按钮旁始终展示资源可用量；不可启动时解释是配额、节点、镜像还是权限原因。
- 终端和代码区域允许横向滚动，保持等宽字体和复制入口，不用彩色背景装饰。

### 5.4 Pipeline / 任务流 / 训练

- 左侧为模板 / 节点目录，中间为流程画布，右侧为节点配置 Drawer；画布节点使用中性表面 + 状态边缘。
- 节点颜色只表达状态：未配置 Neutral、排队 Warning、运行 Running、成功 Success、失败 Danger。
- 运行详情顶部显示任务流 ID、集群、命名空间、创建者、开始时间、耗时、当前阶段和失败节点。
- 资源配置与运行日志并列展示；停止、重试、重新运行必须写明是否复用输出和是否产生新运行 ID。
- 画布连线使用 `#8A979D`，失败分支使用危险色；禁止节点类别彩虹化。

### 5.5 模型与服务

- 服务列表固定显示服务名、模型版本、环境、副本、健康状态、QPS / 延迟和最近发布人。
- 发布流程采用“模型版本 → 资源规格 → 环境 → 健康检查 → 流量策略 → 确认”的步骤；每步显示前置校验。
- 运行中和健康检查使用 Running / Success；发布失败保留日志链接、失败阶段和重试动作。
- 回滚是 Danger 语义，但必须提供目标版本和影响流量范围；灰度 / A-B 使用图表对照，不用彩色大卡。

### 5.6 资源、集群与监控

- 集群页先给拓扑摘要：集群状态、节点数、GPU / CPU / 内存 / 存储利用率、异常节点数。
- 节点与 Pod 列表固定集群、命名空间、资源组、节点 IP / Pod 名称、申请量、使用量和状态。
- 监控图表默认一条信息蓝序列；比较目标用墨黑；阈值线带数值标签。
- 高利用率用 Warning / Danger 文案和动作入口（调整资源、迁移、暂停、联系管理员），不要只把曲线染红。

### 5.7 模型市场 / 智能体

- 模型市场优先使用可筛选目录表格：模型名、任务类型、框架、版本、资源要求、维护状态、最近更新时间。
- 模型详情页以 README、版本、运行要求、示例和部署入口为主；封面图只作辅助，不做大幅视觉主角。
- 资源租赁显示库存、规格、租期、费用和释放规则；费用与运行状态分开表达。

## 6. 状态与可访问性

### 6.1 统一展示词

| 领域 | 状态词 |
| --- | --- |
| 通用任务 | 未启动、排队中、运行中、成功、失败、已停止、已取消、部分完成 |
| Pipeline / 训练 | 草稿、待运行、运行中、暂停、成功、失败、已停止、已归档 |
| Notebook | 创建中、运行中、空闲、已停止、异常、已过期 |
| 镜像构建 | 待构建、构建中、构建成功、构建失败、已下线 |
| 服务 | 未部署、部署中、健康、降级、异常、已停止、已回滚 |
| 数据集 | 草稿、可用、校验中、校验失败、已归档、无权限 |
| 资源 | 可用、使用中、配额临界、已耗尽、离线、维护中 |

展示层不要把同一语义写成多个词，例如不要同时使用“执行中 / 正在执行 / 运行中”；统一为“运行中”。后端原始值可以在详情中作为 source status 展示，但不能作为主标签直接暴露给普通用户。

### 6.2 状态覆盖

所有列表、表格、编辑器、运行详情和发布动作必须覆盖：

| 状态 | 设计要求 |
| --- | --- |
| Loading | 300ms 后显示局部 Skeleton；15s 后提示仍在加载并提供重试 |
| Empty | 说明原因 + 下一步，例如“暂无可用资源 → 配置资源组” |
| Error | 问题、原因、恢复动作；保留筛选和已填内容 |
| Populated | 主路径，默认显示更新时间和范围 |
| Disabled | 控件保留，旁边解释不可用原因 |
| Hover / Focus / Selected | 键盘可达，焦点环不只依赖颜色 |
| Success | 写回对象状态，同时保留日志 / 版本 / 时间 |
| Edge | 超长名称、缺字段、零资源、海量失败行不破版 |
| Permission | 入口按权限隐藏或显示 403；不要让用户点击后才发现无权限 |

### 6.3 可访问性底线

- 正文 / 控件对比度至少 WCAG 2.2 AA；触控目标不小于 32px。
- 图标按钮有 `aria-label`；状态有文字，不只靠颜色。
- 创建任务、启动 Notebook、停止运行、发布服务、查看日志等核心路径可键盘完成。
- 动态进度使用文字状态，必要时 `aria-live="polite"`；避免持续闪烁和无意义动画。
- Modal / Drawer 关闭后焦点回到触发控件；折叠侧栏对图标提供 Tooltip。

## 7. 响应式规则

| 宽度 | 行为 |
| --- | --- |
| ≥ 1440px | 顶栏 + 232px 侧栏 + 主工作区；任务详情可拆三栏 |
| 1100–1439px | 侧栏保留；详情退化为主区 + Drawer |
| 768–1099px | 侧栏折叠为 64px；顶部模块导航允许横向滚动 |
| < 768px | 单主列；表格转为关键字段 + 抽屉详情；操作保留在底部工具栏 |

禁止固定 1920px 画布、绝对定位拼整页和依赖 Hover 才能完成的核心动作。表格、代码和日志在窄屏允许横向滚动；标题、ID 和按钮不能相互遮挡。

## 9. 设计评审清单

- 3 秒内能否看到当前项目 / 集群 / 对象、状态和最严重阻塞？
- 每个区域是否只有一个明确主动作？危险动作是否解释后果？
- 品牌主色是否始终使用墨黑，Logo 彩色面是否没有扩散为业务 UI？
- 状态是否同时有文字、图标 / 色点和可恢复动作？
- ID、版本、时间和资源数值是否可扫描且使用等宽字体？
- 是否覆盖 Loading、Empty、Error、Disabled、Permission、Edge？
- 是否还存在渐变、毛玻璃、大圆角、卡片上浮、彩虹节点或装饰性指标？
- 日志 / JSON / YAML 是否进入深色检视窗，普通业务表格是否保持浅色？
- 首页是否直接呈现资源、任务和服务状态，而不是教程卡片占据第一视觉？
- 窄屏下标题、按钮、表格和日志是否可读、可滚动、无重叠？

## 10. 兼容与发布要求

- 保留 API、数据库 app 标识、镜像仓库路径、已有 URL 和历史资源路径；品牌迁移不与代码仓库重命名绑定在同一发布中。
- 在文档、示例 Pipeline 和 SDK 中增加“ModelOne（原 CubeStudio）”过渡说明，至少保留一个完整版本周期。
- UI 文案、页面标题、favicon、登录页、404 页和加载页先切换为 ModelOne；内部日志和兼容配置可继续显示 CubeStudio。
- 每次迁移页面都要在 1440px、1024px、768px 和 390px 宽度验证布局，并检查长名称、海量表格和无权限状态。
